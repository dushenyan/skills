# 问题重述卡片

第 3 步的产出。它是澄清阶段的终点、执行阶段的输入：用户确认后，同一会话直接开工。

## 使用

固定五块结构：

```markdown
## 问题重述

**目标**：一句话，做完之后什么变好了。

**边界**：做什么 / 不做什么，各一条以上。不做什么尤其重要——
它是「帮我定」的默认值发挥作用的地方。

**关键参数**：（按任务类型取用）
- 读者 / 用户：
- 体量 / 范围：
- 风格 / 基调：

**成功标准**：怎么判断做完了、做好了。可检验，不写「足够好」。

**假设标注**（替你定的，可逐条推翻）：
1. ……
2. ……
```

**假设标注规则**：

- 只放「没问出来、按默认值定的」内容，确定的信息不许混进来。
- 每条假设给出推翻它的代价提示，如「假设用中文撰写，推翻则全文重写」。
- 用户没推翻，就视为接受，执行时不再确认。

## 完整示例

**用户**：帮我写个博客，讲讲我用 AI 编程的体会。

**重述卡片**：

```markdown
## 问题重述

**目标**：发布一篇个人博客，让读者理解 AI 编程改变了什么工作方式。

**边界**：写个人视角的体会与实例，不写工具横评、不写教程。

**关键参数**：
- 读者：懂一点编程、还没深度用过 AI 编程的开发者
- 体量：2000～3000 字
- 风格：第一人称、口语化、实例驱动

**成功标准**：一个没用过 AI 编程的读者读完后，
能说出「值得试的三个理由」和「要避的一个坑」。

**假设标注**（替你定的，可逐条推翻）：
1. 用中文撰写，发布在你自己的博客（推翻代价：换渠道可能要调排版）
2. 基调偏建设性、不吹不黑（推翻代价：偏激基调会改变全文结构）
```

## 要点

- 卡片控制在半屏以内，超过说明澄清没做完，回去补第 2 步。
- 「边界」里至少有一条「不做什么」，它防的是范围蔓延。
- 成功标准必须可检验：能想象出一个具体的人做出具体的判断。
