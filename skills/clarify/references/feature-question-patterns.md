# 提问模式

两阶段提问的具体手法：第 1 步用开放式问题，第 2 步用选择题。

## 使用

**开放式问题（第 1 步框定用）**

瞄准意图而不是参数，让用户讲场景：

- 「想象它做完了，你在什么场景下用到它？」
- 「你想拿它做什么用？」
- 「这件事做成了，什么会变得不一样？」

避免一上来就问参数清单——意图不清楚时，参数问了也白问。

**选择题（第 2 步补缺用）**

设计原则：

1. **选项互斥**：三个选项之间不能重叠。
2. **带具体描述**：不只给标签，给一句「选它意味着什么」。
3. **给「帮我定」出口**：每个问题都有默认值选项，选了技能就替用户定，并记入假设标注。
4. **带推荐**：有明显合理默认时，标注「推荐」并给一句理由。
5. **一次最多 4 题**：超过 4 题用户会开始乱点。

好例子：

```
博客的体量？
A. 短文，1000 字以内，一个观点讲透
B. 标准博文，2000～3000 字（推荐：这类主题的常见体量）
C. 长文，5000 字以上，配完整示例
D. 帮我定
```

反模式：

- 一次抛 8 个开放式问题（用户直接弃疗）
- 选项重叠：「简洁」「极简」「干净」三选一
- 没有「帮我定」，逼用户在不关心的维度上做决定
- 问用户已经说过的东西（「你刚才说要给新手看，那读者是？」）

## 要点

- 第 1 步的开放问题永远围绕场景和用途，不围绕产出参数。
- 选择题的答案要能直接填进重述卡片，设计问题时先想好卡片上哪一格。
- 用户用一句话同时回答了多个维度时，照单全收，不要拆开重新问。
