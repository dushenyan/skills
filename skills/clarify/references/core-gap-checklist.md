# 缺口清单

第 2 步补缺时用。先判定任务类型，再对照清单找还没有答案的维度，只补缺口。

## 使用

| 任务类型 | 必问维度 | 可选维度 |
|---------|---------|---------|
| 写东西 | 读者是谁、核心信息（读完记住什么）、体量 | 风格基调、发布渠道、配图 / 代码示例、标题方向 |
| 做东西（代码） | 用户与场景、核心功能的最小闭环、技术栈 / 运行环境 | 美观要求、是否要部署、可扩展性、测试覆盖 |
| 做决定 | 决策选项、评判标准（最在乎什么） | 时间约束、不可逆性、谁受影响 |
| 学东西 | 现有水平、学到什么程度算够、用途 | 时间预算、偏好媒介（书 / 视频 / 动手）、紧迫性 |

**写东西**追问示例：

- 「读者是懂行的还是新手？这决定第一段怎么写。」
- 「如果读者只能记住一句话，你希望是哪句？」

**做东西**追问示例：

- 「第一版只要能跑通一个最小场景，你心里那个场景是什么？」
- 「技术栈有既定偏好，还是让我推荐？」

**做决定**追问示例：

- 「如果两个选项只能保住一个优点，你保哪个？」
- 「这个决定多久内要定下来？」

**学东西**追问示例：

- 「你现在对这个主题知道多少？零基础还是用过但不深入？」
- 「学到能干什么程度就算达标：能聊、能用、还是能教？」

## 要点

- 必问维度最多 3 个，可选维度按需取用，总数守住硬规则上限。
- 「体量」「美观」这类主观维度，永远给「帮我定」的默认值选项。
- 判错任务类型不要紧，用户的回答会纠正它；但重述卡片前必须改正。
