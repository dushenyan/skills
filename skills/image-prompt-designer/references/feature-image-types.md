# 图类型与版式骨架

选型依据是**这张图要完成什么任务**，不是好看程度。任务判断错，版式再精致也传达不到。

## 先分两大类

| 图的任务 | 类型 | 判断信号 |
|---|---|---|
| 让人看清结构、流程、数据 | 信息型 | 需求里出现「说明」「流程」「对比」「架构」「几层」 |
| 让人感受到主体、氛围、质感 | 表达型 | 需求里出现「好看」「氛围」「质感」「封面」「宣传」 |

信息型看逻辑关系选型，表达型看用途选型。两者可以组合，但一张图只能有一个主任务。

# 一、信息型

## 快速选型

| 内容关系 | 选这个 | 不选那个 |
|---|---|---|
| 并列、互不依赖 | 卡片网格 | 流程图 |
| 有先后顺序 | 横向流程 | 卡片网格 |
| 层层包含 | 分层堆叠 / 同心圆 | 并列卡片 |
| 系统组成与调用 | 架构框图 | 主视觉插画 |
| 随时间变化 | 时间轴 | 流程箭头 |
| 两个方案取舍 | 对比双栏 | 单列清单 |
| 数量对比 | 图表风格插画 | 纯装饰插画 |

## 卡片网格

**骨架**：标题区 + 2×2 或 1×3 等距卡片，卡片内含图标、短标题、一行说明。

**必备**：卡片尺寸一致、间距相等、每卡信息量对齐。

**失败点**：数量不整除导致末行空缺时，改成 8 张或 6 张；每张配不同图标会显得杂乱，统一用线性图标。

## 对比双栏

**骨架**：中轴分隔，左右两栏同构——同样的行顺序、同样的信息槽位。

**必备**：两个方案用同一种视觉语法；差异项用强调色标出，其余中性。

**失败点**：左右信息不对称，读者会以为在比两件不同的事。

## 横向流程

**骨架**：3~5 个节点横排，节点间用箭头，节点上方编号。

**必备**：节点形状一致、箭头长度一致、编号连续。

**失败点**：超过 5 步横排会挤压，改两行折返或泳道；箭头方向不统一。

## 泳道图

**骨架**：纵轴区分角色或系统，横轴是时间或步骤，交叉处放动作块。

**必备**：泳道标签固定在左侧，跨泳道动作用箭头明确指向。

**失败点**：泳道超过 4 条，字号会被压到看不清，应拆成两张图。

## 分层堆叠

**骨架**：等同宽的三到五层从下往上堆叠，层标签左侧对齐。

**必备**：层高一致，层名统一用名词短语。

**失败点**：层间有包含关系却没画嵌套；层数过多导致最上层被裁切。

## 同心圆

**骨架**：中心为核心，向外两到三圈，每圈一个层级。

**必备**：圈间边界明确，标签不压在圆环线上。

**失败点**：超过三圈文字无处安放；各圈元素数量不均导致失衡。

## 架构框图

**骨架**：按调用方向分区（客户端 / 服务 / 存储），区块内是小矩形节点，连线表示调用。

**必备**：分区底色有区分、连线只表示主要调用、节点命名统一。

**失败点**：连线交叉成蜘蛛网。减少细节层级，次要调用放图注。

## 时间轴

**骨架**：一条主轴，节点均匀分布，说明上下交替。

**必备**：主轴只有一条，时间格式统一。

**失败点**：节点间距不等距却暗示时间间隔；说明长短悬殊导致重心偏移。

## 图表风格插画

**骨架**：一个主数据视觉（柱、折线、环形）+ 数据标签 + 简短结论。

**必备**：坐标轴与单位清楚，数值直接标在图形上，不依赖图例。

**失败点**：模型编造虚数或不画坐标轴。数值必须在提示词里给定。

# 二、表达型

## 快速选型

| 用途 | 图类型 | 关键控制点 |
|---|---|---|
| 卖产品、展示细节 | 产品摄影 | 材质、光线、背景干净度 |
| 传达人物与情绪 | 人像 / 场景人物 | 表情、姿态、眼神光 |
| 表达概念或氛围 | 概念插画 | 隐喻是否成立、元素数量 |
| 封面、头图、banner | 海报式构图 | 主体位置、留白、文字区 |
| 图标、贴纸、表情 | 符号化图形 | 轮廓识别度、风格一致 |
| 展示界面想法 | UI 概念图 | 层级、对齐、可读性 |

## 产品摄影

**骨架**：单一产品 + 干净台面或背景 + 一主光一辅光 + 大面积留白。

**必备**：材质描述（哑光 / 金属 / 玻璃 / 皮革）、光线方向、景深。

**失败点**：背景堆道具抢主体；高光过曝丢失材质；多个光源导致阴影方向打架。

**提示词要点**：写清产品朝向与摆放角度，否则模型默认正面平铺，毫无立体感。

## 人像 / 场景人物

**骨架**：单一人物 + 环境交代 + 一个动作瞬间 + 明确光源。

**必备**：景别（特写 / 中景 / 全身）、视角高度、光线性质（柔光 / 硬光 / 侧逆光）。

**失败点**：手部与肢体畸变、眼睛无神、背景人物重复；正午顶光导致面部阴影杂乱。

## 概念插画

**骨架**：一个视觉隐喻 + 少量辅助元素 + 明确色板。

**必备**：隐喻要能被一句话讲清；元素不超过五个。

**失败点**：元素堆砌成拼贴；隐喻过于私人化，读者看不懂；风格在写实与卡通之间摇摆。

## 海报式构图

**骨架**：一个视觉中心 + 大面积留白 + 预留文字区（标题、副标题、角标）。

**必备**：主体不压在文字预留区；视觉重心在上三分之一或黄金分割点。

**失败点**：元素铺满整幅，文字只能压在画面上；上下左右留白不均。

## 符号化图形

**骨架**：单一轮廓 + 最多两色 + 统一描边粗细。

**必备**：缩小到 32px 仍可辨认；一组图标共享同一视觉语法。

**失败点**：细节过多导致缩小后糊成一团；一组图标混用填充与线性两种风格。

## UI 概念图

**骨架**：一到两个屏幕 + 明确的信息层级 + 真实间距。

**必备**：栅格对齐、字号层级、留白比例。

**失败点**：文字全是乱码或伪英文；控件大小随意；截图感弱、像示意图。

**提示词要点**：写明「界面文字留空或仅用短标签」，模型无法可靠渲染成段文案。

# 三、跨类型通用规则

1. **一个视觉中心**：第一眼只能落在一个地方，其余元素为它服务。
2. **对齐产生秩序**：所有块至少共享一条对齐线，秩序来自对齐而非装饰。
3. **数量与画幅匹配**：横向画幅放 3~5 块，纵向放 3~4 块，超出就降级为两段式。
4. **细节服务于识别**：信息型加细节是为了讲清关系，表达型加细节是为了传达质感，与任务无关的细节一律删。
