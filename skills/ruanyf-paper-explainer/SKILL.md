# 论文解读生成器（阮一峰风格）

本 Skill 用于把用户给出的一篇论文或技术长文（PDF / 链接 / 标题皆可），改写成一篇**通俗、好读、有观点**的中文解读文章。叙事语气对齐**阮一峰老师**，排版规范对齐[《阮一峰中文技术文档的写作规范》](https://github.com/ruanyf/document-style-guide)，文章结构参照本仓库的标杆样例——

`technicals/Papers/Attention Is All You Need 论文解读.md`

这是本 Skill 的“满分答卷”。动手写之前先通读一遍，写不出来的时候就回去看它一眼。

## 一、核心要点速览（生成前先读这一节）

> 这一节是硬指标清单。后面各章只是对它的展开。

- **先讲“为什么”，再讲“是什么”**：任何新概念出现前，先交代它要解决什么痛点。绝不一上来就甩定义、甩公式。
- **零基础也能读懂**：假设读者是懂一点编程、但完全没接触过这篇论文的人。每个抽象概念都配一个生活化类比。
- **公式必须逐块拆解**：论文里的核心公式不能直接贴出来就完事，要一层一层拆开讲，每个符号都说明白“它在干什么”。
- **保留原文出处**：文章开头用引用块列出论文原文链接、作者、发表场合、地位，并在正文引用原句时用引用块标出（可附一句“翻译成人话”）。
- **结尾必须给“背不下来时记这 5 点”**：用编号列表把全文压成 5 条以内。
- **正文中文 + 全角标点**（，；：（）「」或“”）；代码块、公式、URL、命令、参数内保持英文标点。
- **中英文之间加一个半角空格**（如 `Transformer 架构`、`8 个头`），这是阮一峰排版的招牌细节。
- **不使用分割线 `---`** 分隔章节，靠标题层级自然区隔；章节之间最多允许一处 `---`（用于分隔“元信息块”与正文）。
- **体量对齐标杆样例**（约 350～400 行）：讲透，但不注水。宁可砍掉次要章节，也不凑字数。

## 二、何时触发

用户出现以下意图时调用：

- “帮我解读/精读/讲解这篇论文”
- 给出一篇 PDF、一个 arXiv 链接、或一个技术长文链接，要求“讲清楚”
- “把这篇 paper 变成人话”“写一篇论文解读”
- 要求按《Attention Is All You Need 论文解读》这个样式写另一篇

**硬规则：先头脑风暴，再动笔**。以下两种情况，**必须**先调用 clarify 技能（按技能名加载），没有任何例外：

1. **用户明确要求头脑风暴**——说出“头脑风暴”“brainstorm”“先别写，我们聊聊”“帮我梳理一下思路”等意图时，无论需求看起来多具体，都先调用 clarify 走完澄清流程，用户确认后才进入本技能的写作。
2. **用户给的是模糊表述**——不是具体论文材料，而是一句简短的直接表述或提问（如“语义检索是什么时候？”“讲讲 RAG 吧”），对象、范围都还没定。此时先调用 clarify 进行头脑风暴式澄清（要解读哪篇/哪几篇论文、读者水平、侧重面等），拿到确认后再写作。

禁止拿着模糊表述或未经头脑风暴确认的需求直接猜一篇论文开写。

反触发：用户只是要摘要、要翻译、要列参考文献、要对比多篇论文的表格——这些不是“解读文章”，按用户具体要求处理即可。

## 三、核心约束

### 1. 先拿到全文，再动笔

- 用户给链接：用 WebFetch 抓取正文，**尽量抓全**（各级标题、关键段落、图表说明、附录）。抓不全就在文中诚实说明“原文此部分未获取到”。
- 用户给 PDF：用可用的 PDF 工具读全文，重点抓摘要、引言、方法、实验、结论、附录。
- 用户只给标题：先用 WebSearch 找到原文（优先 arXiv / 官方博客 / 期刊），抓全文后再写。
- **严禁凭记忆编造论文内容**。数字、指标、结论、作者名一律以抓到的原文为准；拿不准的就不写。

### 2. 元信息块必须准确

文章开头固定用引用块给出（字段按论文实际情况增减，宁可少写不可写错）：

```
> **论文**：[《标题》中文翻译版](相对或绝对链接)
>
> **原文**：[英文原文/官方链接](链接)
>
> **作者**：（作者名，机构）
>
> **发表**：（年份，会议/期刊；如果是博文就写“官方工程博客”）
>
> **地位**：（一句话点出它在领域里的位置，这是全篇的“钩子”）
```

- 链接**必须验证可访问**，死链一律替换或删掉，禁止编造 URL。
- **地位**这一栏是全文的悬念所在，要写得有分量但不吹牛，例如“现代大模型时代的创世论文”。

### 3. 引用原文的方式

引用论文原句时，用引用块，并紧跟一句“翻译成人话”：

```
> 原文：多头注意力允许模型在不同位置联合关注来自不同表示子空间的信息。
>
> 翻译成人话：8 个头可以各学各的，分工干活。
```

不要大段粘贴原文，一段引用不超过三四行。

### 4. 公式处理

- 定界符只有两种：行内公式用 `$...$`，独立公式用 `$$...$$`。**严禁**用 `\(...\)`、`\[...\]`、math 代码块等其他写法。
- **行内公式**嵌在句子中间，`$` 与公式体之间不留空格，与相邻中文之间留一个半角空格；但后接全角标点时不留空格。写法示例：
  - `把问题 $x$ 编码成的向量`
  - `两个向量做内积 $\mathbf{d}(z)^\top \mathbf{q}(x)$，结果越大说明越相关`
- **独立公式**用 `$$...$$`，单独成行，前后各留一个空行：

  ```markdown
  $$ p_\eta(z|x) \propto \exp\left(\mathbf{d}(z)^\top \mathbf{q}(x)\right) $$
  ```

- 公式出现后，**必须**用分步骤文字把它拆开，说明每一步在做什么、为什么这么做。
- 公式里的关键符号首次出现时给出中文解释。
- 如果论文的核心贡献根本不含公式，就不要硬造公式。
- **公式显示自检（硬性）**：写完后逐个检查——
  - 定界符配对完整：`$` 成对出现、`$$` 成对出现，没有漏闭合；行内公式不要误用两个 `$`。
  - LaTeX 命令拼写正确且反斜杠未被吃掉：`\mathbf`、`\top`、`\sum`、`\prod`、`\approx`、`\left(` 与 `\right)` 等。
  - 上下标的花括号配对完整，如 `x_{1:i-1}`、`p_\theta`。
  - 公式内部保持英文半角标点；与两侧中文之间留半角空格，但全角标点前不留空格。

### 5. 语言与标点

- 全程中文撰写。
- 正文用全角标点：`，` `；` `：` `（` `）` `。` `、`。**严禁正文混用半角标点**。
- 以下内容保持英文半角：代码块内、行内代码 `` ` ``、公式、URL、命令行、配置键值。
- 中英文之间加半角空格；数字与中文之间是否加空格需全篇统一（推荐统一加，如 `6 层`、`8 个头`）。

## 四、叙事风格：阮一峰写法规范

> 这一节是硬性要求，不是建议。

### 1. 六大特征

**① 问题驱动，先讲“没有它会怎样”**
- 讲新概念前先讲痛点，再讲解法。经典句式：“如果你想 X，但 Y 很难做到，那么 Z 就是答案。”
- 反例（禁止）：`Transformer 提出了多头注意力机制。`
- 正例：`单一注意力像个全才，什么都管，结果什么都管不好。作者想——不如雇个专家团队，各管一摊。`

**② 从“为什么会有这篇论文”讲起**
- 一句话交代论文的诞生背景：谁做的、为了解决什么历史问题。点到为止，不写成学术综述。

**③ 口语化短句**
- 一句话能说清绝不用两句。多用句号，少用长从句。
- 主动句优先。多用“你”“我们”做主语，像跟朋友聊天。
- 善用“其实”“不过”“打个比方”“说到这里”等过渡词。
- 反例：`该机制通过引入注意力权重以替代循环结构，从而提升并行化能力。`
- 正例：`它把“排队读”改成了“一页纸摊开，全部词同时看”。这就是它能并行的原因。`

**④ 生活化类比**
- 每个抽象概念配一个类比。类比三原则：**贴**（读者熟悉的场景）、**准**（机制对应得上）、**短**（一两句讲完）。
- 标杆样例里的类比可参考：查字典（Query/Key/Value）、排队读书（RNN）、传话游戏 vs 直接打电话（长距离依赖）。
- 格式：`**想象你去图书馆查资料**：……` 或 `**打个比方**：……`

**⑤ 偶尔的作者视角**
- 每章最多 1～2 处，点到为止。句式如“这个细节值得单独说，因为它展示了作者的思考深度”“第一次看到这个设计，我愣了一下”。
- 禁止鸡汤味、煽情、卖课腔。

**⑥ 结尾留“记忆钩子”**
- 全文最后给“记不住全部？只需要记住这 5 个要点”，用编号列表压成 5 条以内。
- 每条一句话，最后一条通常落到“它的意义/影响”上。

### 2. 禁用写法清单

严禁出现：

- `综上所述`、`由此可见`、`总而言之`、`本文将详细介绍` —— 学术腔
- `所谓 XXX 就是`、`作为一个 XXX` —— 教材腔
- `值得我们注意的是`、`需要特别强调的是` —— 官腔
- `本教程将带领大家` —— 客套腔
- `小伙伴们`、`老铁们` —— 过度口语腔
- `非常重要！！！`、`必看！！！` —— 卖课腔
- 连续超过 40 字无标点的长句
- 无具体内容的空泛形容（“极其强大”“完美解决方案”）

### 3. 风格自检清单

每篇生成完毕后逐条勾选：

- [ ] 开篇是不是先讲“这篇论文在历史上是什么位置”，而不是直接定义？
- [ ] 每个抽象概念有没有配生活化类比？
- [ ] 核心公式有没有逐块拆解？
- [ ] 每个公式的定界符是否配对完整（行内 `$...$`、独立 `$$...$$`），没有 `\(`、`\[`、math 代码块写法？
- [ ] 段落平均句长是否在 30 字以内？
- [ ] 有没有至少一处“作者视角”的轻量表达？
- [ ] 结尾有没有“记不住全部？记住这 5 点”？
- [ ] 是否避开了禁用清单里的所有表达？
- [ ] 中英文之间是否加了空格？

## 五、文章结构模板（八段式）

> 这是骨架，不是镣铐。论文本身没有的内容（比如纯理论论文没有“工程细节”）就砍掉对应章节；论文有而模板没有的重要部分，就大胆加章。**编号按实际生成结果重排，不留空章、不跳号。**
>
> 完整可复制模板见 `references/article-template.md`。

| 章节 | 作用 | 必备 |
|---|---|---|
| 元信息块 | 原文链接、作者、发表、地位 | 是 |
| 一、先搞清楚：它在 XX 史上是什么位置？ | 类比开场，讲前史与颠覆点 | 是 |
| 二、这篇论文要解决什么问题？ | 背景 + 主流方案的缺陷 | 是 |
| 三、核心概念逐个拆解 | 全文主体，概念 + 公式 + 类比 | 是 |
| 四、拼装完整架构/机制 | 把零件组装成整体 | 视情况 |
| 五、为什么它赢了？ | 对比论证（表格对比） | 视情况 |
| 六、训练/工程/实现细节 | 让方案落地的参数与取舍 | 视情况 |
| 七、实验结果 | 用数据说话（表格） | 视情况 |
| 八、总结与回望 + 5 个要点 | 意义与影响 | 是 |

各章的写法要点：

**元信息块**：见第三章第 2 节。后面直接接 `---` 与正文分隔。

**一、先搞清楚：它在 XX 史上是什么位置？**
- 用一句话类比点出“旧的做事方式”（如排队读书），再点出“它改成了什么”（一页纸摊开同时看）。
- 标题里带上领域名，如“这篇论文在 AI 史上是什么位置？”

**二、要解决什么问题？**
- 先讲当时的主流方案，再讲它的硬伤。方案通常有 2～3 个，每个一小节。
- 原文的痛点陈述用引用块 + “翻译成人话”。

**三、核心概念逐个拆解**
- 这是最花力气的一章。一个概念一个小节。
- 每个概念：**痛点 → 直觉/类比 → 定义 → 公式（如有）→ 逐块解释**。
- 容易被忽略但精妙的设计，单独拎出来讲（标杆样例的 3.4 节“为什么除以 √dk”就是范例）。

**五、为什么它赢了？**
- 用对比表格。表头加粗，表格后必须有一段文字总结。
- 标杆样例用了“计算复杂度 / 顺序操作数 / 最大路径长度”三指标，这种“三表对比”是最有说服力的写法。

**六、训练/工程/实现细节**
- 挑对读者有用的参数讲（数据集、硬件、学习率、正则化）。
- 每个参数都要解释“为什么这么设”。

**七、实验结果**
- 用表格列关键指标，表格后给 2～3 条硬核结论（质量如何、成本如何）。

**八、总结与回望 + 5 个要点**
- 先引用论文自己的结论，再讲“今天回头看，它的意义远超论文本身”，给 3～4 条影响。
- 最后用小节标题“记不住全部？只需要记住这 5 个要点”，编号列表收尾。

## 六、写作细则

### 1. 标题层级
- `#` 文章标题，`##` 一级章节（用“一、二、三”中文序号），`###` 二级小节（用“3.1、3.2”编号）。
- 一级标题下不能直接出现三级标题。
- 避免孤立编号（同级只有一个子标题时，直接并入父级）。
- 谨慎使用四级标题，并排内容优先用项目列表或 `**（1）（2）（3）**` 编号。

### 2. 强调与标注
- 关键概念用 `**加粗**`，或 `> **一句话**：解释` 的引用块。
- 类比用 `打个比方。` / `**想象你去图书馆查资料**：` 开头。
- 原文引用用引用块，紧跟“翻译成人话”。
- 不要滥用加粗，一个段落最多一处。

### 3. 公式与表格
- 行内 `$...$`，独立 `$$...$$`（详见三章 4 节公式处理）。
- 对比类信息一律用表格，表头加粗，表格后必须跟文字总结。
- 表格里的希腊字母、上下标用 LaTeX 写法与正文保持一致。

### 4. 配图建议（可选）
如果某处确实需要一张架构图/流程图，用引用块给出配图建议，方便用户交给图片工具生成：

```
> **配图建议**：
> - 用途：说明 XXX 流程
> - 画面描述：<具体的中文画面描述>
> - 风格：技术线框图 / 等距示意图 / 流程图
```

整篇不要超过 2～3 处，能文字讲清的就不用图。

## 七、生成流程

0. **判断输入形态**：用户给的是具体论文（PDF/链接/标题）还是模糊表述？用户是否明确要求头脑风暴？
   - 用户要求头脑风暴或给的是模糊表述（如“语义检索是什么时候？”）→ **必须**先调用 clarify 技能澄清（确认要解读的论文、读者、侧重面），拿到确认的重述卡片后再回到第 1 步。
   - 具体论文且无头脑风暴要求 → 直接进入第 1 步。
1. **取全文**：按第三章第 1 节抓取论文全文（WebFetch / 读 PDF / WebSearch + WebFetch）。
2. **提炼骨架**：列出论文的摘要、核心贡献（一般 1～3 条）、方法要点、实验结论、局限性。
3. **定“地位”**：用一句话概括这篇论文在领域里的位置，作为元信息块和开篇的钩子。
4. **规划章节**：以八段式为骨架，按论文实际内容取舍、增删，重新编号，不留空章。
5. **设计类比**：为核心概念各想一个“贴、准、短”的类比。这一步决定文章好不好读。
6. **逐章撰写**：贯彻第四章六大特征；公式逐块拆解；原文引用加“翻译成人话”。
7. **写 5 点总结**：把全文压成 5 条以内。
8. **自检**：对照第三章（标点/链接/**公式显示**）、第四章第 3 节（风格清单）逐条核对，重点逐个检查公式的定界符配对与 LaTeX 命令。
9. **收尾交付**：保存文件后，按第八章「对话收尾」在对话里简要汇报并附问题选项。

## 八、输出格式

- 输出为**单个 Markdown 文件**，存放在论文所在目录（默认 `technicals/Papers/`）。
- 文件命名：`<论文标题> 解读.md`，如 `Building Effective Agents 解读.md`、`BERT 论文解读.md`。
- 若标题含 `:` `/` 等不适合做文件名的字符，用空格或 `-` 替换。
- 文件名沿用仓库现有的中文命名习惯，不使用拼音。
- **禁止在文件开头添加“本文件由 AI 生成”之类的声明**，正文从元信息块直接开始。

**对话收尾（硬性）**：文件写完后，在对话里的汇总必须以**带编号的问题选项**结尾，让用户直接选下一步。汇报本身一两句话即可（文件路径 + 一句话说明），选项要具体可操作。示例：

```
解读已写好：technicals/Papers/RAG 论文解读.md（约 200 行，含公式逐块拆解与 5 点总结）。

接下来可以：
1. 深入某一章再展开（如“两种 RAG 变体的区别”）
2. 调整类比或侧重面，换个讲法
3. 检查并修正所有数学公式的显示
4. 按同样格式解读另一篇论文
```

禁止用“写好了！这篇解读走的是‘两者结合’路线：”这类自我点评式说辞收尾——不要替用户总结“路线”，把选择权交回给用户。

## 九、示例对话

**用户**：解读一下这篇论文 https://www.anthropic.com/engineering/building-effective-agents

**Skill 行为**：
1. WebFetch 抓取全文，确认作者、发布日期、全部章节与小节。
2. 提炼核心主张：最成功的实现用的是简单可组合的模式，而非复杂框架。
3. 定“地位”：把“何时该用 agent、何时不该用”讲清楚的一篇纲领性文章。
4. 以八段式规划章节：把 5 种工作流各立一节，附录的 ACI 设计单独成章。
5. 为每个概念配类比（工作流像流水线、agent 像能自己拿主意的员工、ACI 像给新同事写接口文档）。
6. 逐章撰写，公式/原文引用按规范处理。
7. 结尾给“记不住全部？记住这 5 点”。
8. 保存为 `technicals/Papers/Building Effective Agents 解读.md`。
9. 对话收尾：一句话汇报文件路径，附编号问题选项（深入某章 / 调整讲法 / 检查公式显示 / 解读下一篇）。

**用户**：语义检索是什么时候？

**Skill 行为**：
1. 第 0 步：这是一句模糊表述，没有具体论文——先调用 `clarify` 技能澄清。
2. 澄清后确认：用户想读的其实是某篇具体论文（如 ColBERT），读者是懂一点编程的新手。
3. 拿到确认的重述卡片后，回到本技能第 1 步，按正常流程抓全文、写解读。
