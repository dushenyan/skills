# 学习与理解

帮用户深入理解技术概念、论文或机制。典型入口：「X 和 Y 有什么区别」「为什么 X 能工作」「我这样理解对吗」。

## 使用

学习场景的核心方法：**费曼技巧 + 苏格拉底**。用户自以为懂的地方，让他讲一遍、用一遍、错一遍，理解漏洞会自己浮出来。

追问重点：

1. **复述检验**：用自己的话讲，不给定义。
   - 「先不看资料，你能用自己的话说说 X 是干什么的吗？」
   - 「如果 X 突然从世界上消失了，哪些事情会坏掉？」（反事实检验）
2. **边界探测**：概念适用的边缘在哪里。
   - 「有没有 X 不适用的场景？那个场景里缺了什么条件？」
   - 「X 的最小可用例子是什么？把规模压到最小它还成立吗？」
3. **类比压力测试**：类比在哪里失效。
   - 「你刚才用了『像水管』的类比。水管的哪个特性是这个概念没有的？」
4. **机制追问**：从「是什么」逼到「为什么」。
   - 「它为什么必须这样设计？如果不这样，会在哪一步出问题？」
   - 「这个设计第一次被提出时，是为了解决什么痛点？」
5. **教给新手**：
   - 「假设要给一个刚入门的同事讲明白这个，你会从哪个例子开始？」

对话示例片段：

> **用户**：我觉得我理解 Transformer 的注意力机制了。
>
> **技能**：那不看资料，你能用自己的话说说：它到底替模型解决了什么问题？如果去掉它、换回老方案，具体哪里会坏？
>
> **用户**：就是……能同时看所有词，不用排队。
>
> **技能**：`> 我听到的是：你抓住了「并行」这一层，但「相关性加权」还没浮出来。` 那我再追问一步：如果只是同时看所有词、但每个词一视同仁，够吗？缺的那一步是什么？

## 要点

- 「你能解释它」是最大的幻觉区，复述检验永远放在第一个。
- 用户举的类比一定要压力测试，类比失效的地方就是理解的边界。
- 用户卡住时给脚手架：一个更小的问题、一个具体例子，而不是答案。
- 论文场景可与 `ruanyf-paper-explainer` 技能衔接：先苏格拉底式检验理解，再生成解读文章。
