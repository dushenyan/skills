# 诊断清单

扫描 `skills/*/` 时逐技能、逐维度过这张清单。判级的目的不是打分本身，而是决定报告里的排序和修复顺序：P0 不修技能就不可用或不可信，P1 影响代理能否正确触发技能，P2 只是维护体验问题。
## 维度一：frontmatter 合规

| 检查项 | 判级 | 说明 |
|-------|------|------|
| `name` 与目录名一致 | P0 | 目录名是唯一事实来源，两者不一致时以目录名为准改 frontmatter |
| `description` 存在且非空 | P0 | 代理靠它决定是否加载，缺失等于技能隐身 |
| `metadata.author` / `version` / `source` 齐全 | P2 | 仓库规范字段；`version` 需为 `YYYY.M.D` 日期格式 |
| `description` 字符数在 300~700 | P1 | 判定细则见 [core-description](core-description.md) |

## 维度二：description 三要素

| 检查项 | 判级 | 说明 |
|-------|------|------|
| 能力层：一句话说清核心产出 | P1 | 只有「做什么」没有另外两层是最常见的扁平描述 |
| 触发层：2~4 个用户会说的话或场景 | P1 | 抽象词（「需要时使用」）不算触发层 |
| 边界层：反触发或与兄弟技能的分工 | P1 | 有相邻技能时必须写分工，避免两个技能抢同一触发 |

## 维度三：SKILL.md 结构

| 检查项 | 判级 | 说明 |
|-------|------|------|
| frontmatter 后紧跟 `# 标题` | P0 | 入口文件的骨架 |
| 开篇一段话说明解决什么问题、何时使用 | P1 | 让加载者 10 秒内建立心智模型 |
| 「核心参考」表格存在且非空 | P1 | 仓库规范的结构；空表说明细节全堆在正文了 |
| 表格链接指向的文件真实存在 | P0 | 断链的参考等于死路 |
| 正文是索引+工作流，不是细节堆砌 | P2 | 判据：正文 >150 行且含大段手法讲解时，提示应拆到 references/ |

## 维度四：references/

| 检查项 | 判级 | 说明 |
|-------|------|------|
| 文件名带类别前缀（`core-` / `feature-` / `best-practices-` / `advanced-`） | P2 | 仓库命名约定 |
| 每个文件有自己的 frontmatter（`name` + `description`） | P1 | 按需加载的依据 |
| 无孤儿文件：目录里的文件都被 SKILL.md 引用 | P2 | 孤儿文件不会被任何入口加载到，要么补引用要么合并删除 |
| SKILL.md 引用的文件都存在（与维度三的断链检查互为镜像） | P0 | 同一条断链只报一次 |

## 维度五：同步性

| 检查项 | 判级 | 说明 |
|-------|------|------|
| `GENERATION.md` 存在且含来源与时间 | P2 | 便于日后判断是否需要重新整理 |
| README.md 清单与 `skills/` 目录一致 | P1 | 多出、缺失、描述不符都算；细则见 [feature-sync](feature-sync.md) |

## 维度六：技能间引用网络

技能不该是孤岛——用户的需求往往横跨多个技能，相邻技能之间有分工引用，代理才能把用户导到正确的那一个。本仓库的已知相邻组：阮一峰写作系（`ruanyf-answer-style` / `ruanyf-document-style-guide` / `ruanyf-paper-explainer`，`tech-tutorial` 的叙事语气也属此系）、求职系（`inspect-resume` / `project-highlights-extractor` / `interview-simulator`）、思辨写作系（`clarify` / `socratic` / `article-readability-rewriter`）。诊断时以触发词重叠和用户流程上下游为准重新判断，不限于这三组。

| 检查项 | 判级 | 说明 |
|-------|------|------|
| 功能相邻的技能对有互相引用（description 边界层分工句或正文交叉引用块） | P2 | 只有一方提另一方也算；两边都没提才算孤岛 |
| 引用指向的技能名真实存在且拼写正确 | P0 | 引用了不存在的技能是硬错误，多半是改名残留 |
| 同风格系技能的风格特征表述一致 | P2 | 阮一峰系技能对「短句白话、生活化类比」等特征的描述若互相矛盾，用户会拿到互相打架的指令 |

## 要点

- 同一文件的问题合并成一条报告项，标最高判级，避免报告碎片化。
- 扫描结果先落成一张总表（技能 × 维度 × 判级），报告从总表生成，修复后复扫也用同一张表对照。
- P1 和 P2 的修复建议要具体到「怎么改」，不能只说「不达标」。
