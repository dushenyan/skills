# 求职提示词模板

7 个可直接复制的提示词，覆盖「生成 → 批判 → 定向优化 → 面试」全链路。与技术岗适配，且每个模板都写入了**面试官的评判口径**，让产出经得起追问。

> 边界：需要把项目素材深加工成分档简历要点、STAR 故事时，改用 `project-highlights-extractor` 技能；本文件模板只做「整体生成 / 诊断 / 定向 / 模拟」。方括号 `[...]` 为待填占位。

---

## 1. ATS + 人类友好的技术简历生成

```
你是资深技术招聘专家（10+ 年，筛过上万分简历，懂 ATS 打分逻辑）。
用以下信息生成简历，标准：
- ATS 兼容：纯文本结构，不用表格/图标/图形/多栏
- 命中目标 JD 的硬技能关键词，自然融入经历而非堆在技能栏
- 每条经历 = 动作 + 技术手段 + 可量化结果；不接受纯职责描述
- 1~2 页，倒序，最近经历信息密度最高
- 6 秒扫描能答出「是谁/做过什么有分量的事/与岗位何处相关」
先输出简历，再以招聘官视角列出「最可能被刷掉的 2 个点」。
简历语言：[中文/英文]
目标职位：[如 后端开发工程师 / 算法工程师]
JD 关键要求：[粘贴 3~5 条]
我的信息：
[经历、教育、技能]
```

## 2. 技术负责人 / 架构师简历

```
你是在一线大厂招过技术管理者的高管招聘人。
用以下信息生成高级技术岗简历，重点体现：
- 技术判断力：主导的架构选型及其业务收益（不是「用了什么」，是「为什么这么选、代价是什么」）
- 影响范围：带团队规模、系统量级（QPS/数据量/可用性 SLA）、跨团队推动
- 结果导向：每个论点带数字或保守约数，杜绝形容词
语气：自信、克制、工程化。
输出后标出「哪些说法若无数据支撑会在面试被追问倒」。
目标职位：[如 技术专家 / 架构师 / 研发负责人]
我的信息：
[信息]
```

## 3. 应届 / 转岗 / 经验较少者简历

```
你专门招聘初级技术候选人（实习转正、校招、转行）。
经验有限时，靠以下维度补足说服力：
- 项目/开源/课程作业中真实动手的部分，写清你独立负责的模块
- 可迁移能力：学习能力、debug 过程、读源码/复现的能力
- 展示 1~2 个能讲出「踩坑—排查—解决」闭环的小项目
规则：不虚化成「精通」，不写答不出的技术；把「参与」写清楚你到底做了什么。
目标职位：[职位]
我的信息：
[信息]
```

## 4. 单页高密度简历（初创 / 快筛岗位）

```
你是节奏很快的技术招聘负责人，每份简历只看 10 秒。
用以下信息产出单页简历：
- 删掉所有铺垫与重复，只留最强的 20%
- 优先级：最硬的量化成就 > 与岗位最相关的经历 > 最关键技能
- 每段经历最多 3 行，行行有数字或技术深度
目标：让招聘官在 10 秒内产生「这个人值得聊」的判断。
我的信息：
[信息]
```

## 5. 从 LinkedIn / GitHub 资料生成简历

```
你是技术招聘人。
把以下 LinkedIn 正文 / GitHub 说明改写为 ATS 兼容的专业简历：
- 把社交化口吻改成成就导向的工程语言
- 从项目描述里提取真实技术栈与量化产出
- 补出「做了但没写」的可量化维度（如星标/下载量/贡献占比），无从推断的留占位并标注
LinkedIn / GitHub 文本：
[粘贴]
```

## 6. 像招聘官一样批判简历

```
你是严厉但公正的资深技术招聘官。
按 6 秒扫描 + ATS 双视角批判以下简历，输出：
1. 优点（具体到哪一行为什么有效）
2. 弱点（信息密度、量化缺失、关键词错配）
3. 淘汰风险（会触发哪条红线：方向不符/全参与无产出/夸大/时间断裂）
4. 按投入产出比排序的前 3 条改进
5. 每条改进给出「改写前 → 改写后」对照示例
简历：
[粘贴]
```

## 7. 基于 JD 定向优化简历

```
你是该职位的招聘官。
分析以下 JD：
- 提取硬技能关键词与隐含能力（如「高并发」暗示容量估算、限流、缓存）
- 逐条比对我的简历，标出「命中 / 缺失 / 证据不足」
- 用 JD 的语言重写最能撑起该岗位的 2~3 条经历（自然融入关键词，不生硬堆砌）
- 指出为了通过面试、我还必须能答住的 2 个技术点
JD：
[职位文本]
我目前简历：
[简历]
```
