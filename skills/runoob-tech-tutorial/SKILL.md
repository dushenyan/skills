# 通用中文技术教程生成器

按用户给出的技术名称，生成一份**结构完整、内容充实、重点突出**的中文教程：排版对齐 [菜鸟教程](https://www.runoob.com)，叙事语气贴近阮一峰（[ruanyifeng.com](https://www.ruanyifeng.com)），核心章节配一个可运行的项目案例，重点示例同步抽成可运行脚本落到个人示例库 `~/Desktop/engineering_examples`。目标是让读者**一章读透一个知识点**，而不是走马观花。

**一次性交付整份教程**：不要逐章征求确认，也不要写完后逐章回读返工。**章数由知识点决定，不硬凑也不刻意压缩**；常见、高频、易错的知识点必须给足篇幅展开。

## 一、硬指标

| 指标 | 要求 |
|---|---|
| 内容深度 | 每个知识点按「是什么 → 为什么需要 → 基本用法 → 常见场景/变体 → 易踩的坑 → 一句话小结」六要素讲透；不能只给一条命令或一段代码就跳过 |
| 重点突出 | 高频/核心内容用 `> **学习重点 ⭐**` 或加粗小标题显式标注；同一知识点至少给 2~3 个使用变体或场景示例；易错点用 `> **注意**` 单独成块 |
| 覆盖面 | 排目录前先列**知识点清单**（官方文档目录 + 该技术的常见用途），逐项对照章节目录查漏；常用 API、常见配置、典型工作流、生态相关工具全部覆盖；不确定的边界场景宁可多写一段也不要漏 |
| 语气 | 学阮一峰的手感：问题驱动、口语短句、给类比、偶尔一句「我」的观察；讲解段落允许长一些，只要每句话都在讲具体事 |
| 结构 | 以知识点为主线排章，必备骨架不可少，编号连续、不留空章，末章是参考资源 |
| 代码 | 完整自包含、复制即可跑；Python 一律 `uv`（非 Python 用对应生态标准工具）+ Google 风格 docstring；每个示例附预期输出；关键代码行加解释性注释 |
| 命令可执行 | 每条命令复制即执行：不留 `...` / `xxx` 占位；单机示例只给单机能力，副本数与节点数匹配；容器内与宿主机的连接地址分开写；命令与实际部署方式一致；细则见 `references/best-practices-executable-commands.md` |
| 版本 | 用最新稳定版，教程里写明版本号，迭代快的技术注明「后续版本可能有差异」 |
| 配套示例 | 挑 2~5 个最重要的示例抽成编号可运行脚本，落 `~/Desktop/engineering_examples/<主题>/`，照仓库约定：头部 docstring（核心思想/适合场景/学习要点/运行）、计算值用 `calc()` 加下划线、关键结论高亮、结尾要点总结，逐个跑通后正文标注脚本路径 |
| 章末 | 除最后一章外，末尾一行加「下一站建议」引用块，指向实际存在的下一章 |
| 排版 | 正文中文 + 全角标点；代码块标语言；不滥用分割线（单篇 ≤ 2 处）；每 2~3 章一处配图建议 |

细节都在 `references/`，按需查，不要一开始就全读。

## 二、工作流（五步）

**Step 1 · 摸底（搜索不超过 3 次）**

- WebSearch 一次，确认最新稳定版本号与安装方式。
- 要写实战项目，再搜一次官方 Quickstart 当素材。
- 不要为「版本 / 安装 / Demo」各搜一轮以上；查不到就用官方文档对应页面，并注明版本差异。

**Step 2 · 知识点清单与排目录**

读 `references/tutorial-structure.md`，先照官方文档目录和该技术的常见用途列一份**知识点清单**（每项标注「必备 / 进阶 / 可略」），再按参考菜单取舍排章节目录，**逐项对照清单查漏**——漏了要么补章要么并入相关章，确认无遗漏后**直接开写**，不要停下来等确认。

**Step 3 · 一次性写完全部章节**

- 动笔前读一次 `references/narrative-style.md` 找语感，同时对照 `references/tutorial-structure.md` 第二节的「内容深度基线」——每个知识点都要按六要素讲透，不能一句话带过；排版拿不准查 `references/formatting.md`；写实战章节读 `references/project-case.md`。同一份文件整场只读一次。
- 常见/高频知识点至少给 2~3 个使用变体或场景示例；易混概念用对比表；易错点单独用 `> **注意**` 成块提醒。
- 写命令时遵守 `references/best-practices-executable-commands.md`：参数写全、单机示例只给单机能力、容器内与宿主机的连接地址分开写、每节点不同的配置逐台改、不写伪命令。
- 实战章节优先中文 / 国内可访问资源，资源链接必须验证可访问（通常 3~5 条）；其它章节只给官方文档链接，不必逐个访问。严禁编造 URL。
- 写完直接进 Step 4 抽示例，**不要逐章回读、逐章重写**；动笔时顺手记下哪几个示例值得抽进示例库，省得回头翻。

**Step 4 · 重点示例抽进示例库**

从正文里挑 **2~5 个**最能帮读者建立手感的示例（通常是核心用法、对比实验、易错演示这三类），在 `~/Desktop/engineering_examples/` 下**新开一个主题目录**落成编号可运行脚本。动笔前读 `references/code-examples.md`，照仓库约定写：头部 docstring、计算值 `calc()` 下划线、关键结论高亮块、结尾要点总结；只新增目录，不改 `utils.py`/`config.py` 等既有文件。写完**逐个实际运行验证**（LLM 主题用 `USE_MOCK=1` 离线跑通），再回到教程正文，在对应小节末尾标注脚本路径。

**Step 5 · 自查一次，收尾交付**

```bash
python3 scripts/check_tutorial.py <教程目录>
```

脚本只兜底**协作必需的机械项**：文件命名与序号连续、代码块闭合（ERROR）；代码块语言标注、章末「下一站建议」、学习重点标注覆盖度、命令占位符（`...` / `xxx`）只提醒（WARN）。ERROR 改完即止；WARN 扫一眼就好——**WARN 提示某章缺少 `> **学习重点 ⭐**` 或 `> **注意**` 时，回到该章把常见/易错点显式补上**，这是「重点突出」的兜底。标点、字间距、句长、语气等纯写作风格脚本一律不查，写的时候顺手留意即可。

最后再对每个 `bash` 代码块做一次命令审查（四个问题见 `references/best-practices-executable-commands.md` 的「交付前自检」）：能实测的本地跑一遍，不能实测的在命令旁标注前置条件与预期输出。

最后补 `README.md`（目录结构、依赖安装、项目运行方式）和根目录 `_meta.yaml`（教程目录树清单，文件节点带不重复 UUID，规范见 `tutorial-structure.md` 第五节第 4 小节）。

## 三、引用文件

| 文件 | 什么时候读 | 内容 |
|---|---|---|
| `references/narrative-style.md` | 动笔前整场读一次，找语感 | 五条可上手的写法、类比怎么给、什么时候要展开讲、容易出戏的表达、想更严格时的去处 |
| `references/tutorial-structure.md` | 排目录与写作时 | 章节组织原则、参考菜单、**内容深度基线（六要素）**、章末指引规范、三级目录与命名、`_meta.yaml` 目录树规范 |
| `references/formatting.md` | 排版拿不准时 | 标题与分割线、五种引用块（含常见场景/易错点）、代码块、表格、输出标注、配图提示词 |
| `references/project-case.md` | 写实战章节时 | 六小节结构、中文资源范围、链接验证要求 |
| `references/code-examples.md` | 抽配套示例时 | 示例库目录与命名、脚本骨架、高亮/下划线标记、LLM 主题复用 utils、运行验证 |
| `references/best-practices-executable-commands.md` | 写命令与交付前自检 | 占位符、单机/集群错配、连接地址、部署方式一致性、伪命令、前置条件 |

## 四、输出格式

- 三级目录：技术名目录 → 学习阶段子目录 → 章节文件，命名 `<序号>-<中文标题>.md`；完整示例见 `tutorial-structure.md` 第五节。
- 正文从一级标题开始，**不要加「参考来源」引用行**，官方资源统一放最后一章。
- 教程根目录补 `README.md` 与 `_meta.yaml` 目录树清单（UUID 约定见 `tutorial-structure.md` 第五节第 4 小节）；配套示例落在 `~/Desktop/engineering_examples/<主题>/`，正文对应小节末尾标注脚本路径。

## 五、示例对话

**用户**：帮我生成一份 Milvus 教程，菜鸟风格。

**Skill 行为**：

1. 搜一次版本与安装方式，再搜一次官方 Quickstart 作为实战素材。
2. 读 `tutorial-structure.md`，列 Milvus 知识点清单、对照查漏后排章节目录，按「内容深度基线」直接开写。
3. 一口气写完全部章节：每个知识点按「是什么/为什么/怎么用/常见场景/坑/小结」六要素讲透；常见/高频项给 2~3 个变体示例，用 `> **学习重点 ⭐**` 显式标注；易错点单独成块；语气照 `narrative-style.md`、排版照 `formatting.md`、实战章节照 `project-case.md`；每章末尾给「下一站建议」，每 2~3 章一处配图建议，Python 示例用 uv + Google docstring。
4. 挑 2~5 个重点示例（如 Collection 建表、向量插入与检索、分区键对比实验）照 `code-examples.md` 抽成脚本落 `~/Desktop/engineering_examples/milvus/`，计算值下划线、关键结论高亮，逐个跑通后回正文标注路径。
5. 跑 `check_tutorial.py` 把 ERROR 清零、扫一眼 WARN（特别是「学习重点/注意」覆盖度），补 `README.md` 与 `_meta.yaml`，交付。
