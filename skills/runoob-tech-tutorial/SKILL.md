# 菜鸟风格技术教程生成器

按用户给出的技术名称，生成一份循序渐进、通俗易懂、全链路覆盖的中文教程：排版对齐 [菜鸟教程](https://www.runoob.com)，叙事语气贴近阮一峰（[ruanyifeng.com](https://www.ruanyifeng.com)），核心章节配一个可运行的项目案例。

**一次性交付整份教程**：不要逐章征求确认，也不要写完后逐章回读返工。规模由技术本身决定，不硬凑章数。

## 一、硬指标

| 指标 | 要求 |
|---|---|
| 语气 | 学阮一峰的手感：问题驱动、短句口语、给类比、偶尔一句"我"的观察；八九分像即可，不为风格反复改稿 |
| 结构 | 以知识点为主线排章，必备骨架不可少，编号连续、不留空章，末章是参考资源 |
| 代码 | 完整自包含、复制即可跑；Python 一律 `uv`（非 Python 用对应生态标准工具）+ Google 风格 docstring；每个示例附预期输出 |
| 版本 | 用最新稳定版，教程里写明版本号，迭代快的技术注明"后续版本可能有差异" |
| 章末 | 除最后一章外，末尾一行加「下一站建议」引用块，指向实际存在的下一章 |
| 排版 | 正文中文 + 全角标点；代码块标语言；不滥用分割线（单篇 ≤ 2 处）；每 2~3 章一处配图建议 |

细节都在 `references/`，按需查，不要一开始就全读。

## 二、工作流（四步）

**Step 1 · 摸底（搜索不超过 3 次）**

- WebSearch 一次，确认最新稳定版本号与安装方式。
- 要写实战项目，再搜一次官方 Quickstart 当素材。
- 不要为「版本 / 安装 / Demo」各搜一轮以上；查不到就用官方文档对应页面，并注明版本差异。

**Step 2 · 排目录**

读 `references/tutorial-structure.md`，按知识点取舍参考菜单，列出实际章节目录，然后**直接开写**，不要停下来等确认。

**Step 3 · 一次性写完全部章节**

- 动笔前读一次 `references/narrative-style.md` 找找语感（它是语气参考，不是验收标准）；排版拿不准查 `references/formatting.md`；写实战章节读 `references/project-case.md`。同一份文件整场只读一次。
- 实战章节优先中文 / 国内可访问资源，资源链接必须验证可访问（通常 3~5 条）；其它章节只给官方文档链接，不必逐个访问。严禁编造 URL。
- 写完就进自查，**不要逐章回读、逐章重写**。

**Step 4 · 自查一次，收尾交付**

```bash
python3 scripts/check_tutorial.py <教程目录>
```

脚本只兜底**协作必需的机械项**：文件命名与序号连续、代码块闭合（ERROR）；代码块语言标注、章末「下一站建议」只提醒（WARN）。ERROR 改完即止；WARN 扫一眼就好。标点、字间距、句长、语气等写作风格脚本一律不查，写的时候顺手留意即可。

最后补 `README.md`（目录结构、依赖安装、项目运行方式）。

## 三、引用文件

| 文件 | 什么时候读 | 内容 |
|---|---|---|
| `references/narrative-style.md` | 动笔前整场读一次，找语感 | 五条可上手的写法、类比怎么给、容易出戏的表达、想更严格时的去处 |
| `references/tutorial-structure.md` | 排目录时 | 章节组织原则、13 项参考菜单、章末指引规范、三级目录与命名 |
| `references/formatting.md` | 排版拿不准时 | 标题与分割线、四种引用块、代码块、表格、输出标注、配图提示词 |
| `references/project-case.md` | 写实战章节时 | 六小节结构、中文资源范围、链接验证要求 |

## 四、输出格式

- 三级目录：技术名目录 → 学习阶段子目录 → 章节文件，命名 `<序号>-<中文标题>.md`；完整示例见 `tutorial-structure.md` 第四节。
- 正文从一级标题开始，**不要加「参考来源」引用行**，官方资源统一放最后一章。
- 教程根目录补 `README.md`。

## 五、示例对话

**用户**：帮我生成一份 Milvus 教程，菜鸟风格。

**Skill 行为**：

1. 搜一次版本与安装方式，再搜一次官方 Quickstart 作为实战素材。
2. 读 `tutorial-structure.md` 排章节目录，直接开写。
3. 一口气写完全部章节：语气照 `narrative-style.md`、排版照 `formatting.md`、实战章节照 `project-case.md`；每章末尾给「下一站建议」，每 2~3 章一处配图建议，Python 示例用 uv + Google docstring。
4. 跑 `check_tutorial.py` 把 ERROR 清零，补 `README.md`，交付。
