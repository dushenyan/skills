## 一、六小节结构（缺一不可）

### 1.1 项目目标与亮点

- 一句话说明项目做什么、能用到该技术的哪些核心能力。
- 列出本项目**重点体现**的技术亮点（如"本项目重点体现 Milvus 的向量检索 + 标量过滤 + 索引切换"）。

亮点必须具体到能力名，不要写"全面展示 XX 的强大功能"。

### 1.2 项目结构

用目录树展示完整结构（带文件说明），例如：

```
demo-project/
├── README.md          # 项目说明
├── pyproject.toml     # 依赖声明（uv 管理）
├── data/              # 原始资料与样本
│   ├── documents/     # 待处理的文档资料
│   └── README.md      # 资料来源与下载说明
├── src/
│   └── demo_project/
│       ├── __init__.py
│       ├── main.py    # 入口脚本
│       └── ...
└── tests/
    └── test_smoke.py  # 冒烟测试
```

### 1.3 资料下载与准备（中文资源 + 链接必须有效）

每个资源给出四项信息：

- 资源名称
- **来源链接**（已验证可访问，学习者可直接下载）
- 文件大小/格式
- 在项目中怎么用

来源范围与验证要求见本文第二节。

### 1.4 完整代码

- 列出项目**全部源代码**（按文件拆分），保证 `git clone && uv run` 即可跑通。
- 每个文件给出：用途说明 + 完整代码 + 关键代码段解释。

不要用"此处省略 XX 行"来偷懒。学习者拿不到完整代码，这一章就废了。

### 1.5 运行步骤

- 从环境初始化到运行结束，**逐步给出可执行命令**。
- 每步附预期输出。

### 1.6 项目扩展建议

- 给 2~3 个"如果你想进一步改造"的方向（如换数据集、加前端、改成异步）。
- 每个方向说明改造点与涉及到的技术点。

## 二、资源约束：中文优先 + 链接必须验证

> 这一节只约束实战项目章节（端到端 Demo）引用的文档、数据集与参考项目。

### 1. 资源优先中文

项目用到的所有文档、数据集、参考项目，**必须优先选用中文资源或国内可直接访问的来源**，包括但不限于：

- 中文官方文档与国内数据平台：ModelScope、天池、和鲸、飞桨 AI Studio。
- Gitee 上的官方镜像或中文开源项目。
- 模型/权重镜像：`hf-mirror.com`。
- 中文开发者社区的高质量教程与专栏（掘金、知乎等，需甄别内容质量，不搬运低质文章）。

找不到中文资源时，允许使用英文官方原始资源，但需注明"暂无中文资源"，链接同样要验证有效。

为什么这么做：教程的读者在国内，一个打不开的 HuggingFace 原始链接，等于这段教程到这儿就断了。

### 2. 链接必须逐个验证

成文前用 WebFetch 逐个访问每个资源链接，确认页面可打开、内容与描述相符。

出现 404、403、超时或内容已迁移的链接，**必须替换**为可访问的同类中文资源，**严禁保留死链，严禁凭印象编造 URL**。

### 3. 大文件不入库

**禁止**在项目中直接 base64 内嵌大文件，**必须**让用户通过链接自行下载处理。
