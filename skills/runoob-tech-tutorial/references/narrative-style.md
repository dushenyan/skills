# 叙事风格：阮一峰老师写法规范

> 这是硬性要求，不是建议。所有讲解段落都必须贯彻这套风格。

技术内容可以靠查文档补，风格不能。一篇读起来像教材的教程，读者翻两页就走了；一篇读起来像有人在旁边给你讲的教程，读者会一章一章追下去。这份规范就是后者。

## 一、阮一峰风格的六大特征

### ① 问题驱动，绝不堆砌 API

每讲一个新概念，**先讲"没有它会怎样"**，再讲"它怎么解决"。不要一上来就甩接口列表。

经典句式："如果你想 X，但 Y 很难做到，那么 Z 就是答案。"

- 反例（禁止）：`Z 提供了 a()、b()、c() 三个方法。`
- 正例：`你有没有遇到过这种情况：辛辛苦苦写了一堆代码，结果发现数据查得太慢？Z 就是为了解决这个痛点。`

### ② 从"为什么有这个技术"讲起

简要交代技术**诞生背景**（谁做的、为什么做、解决了什么历史问题）。

涉及知名人物/团队时，可以一句话点出（如"它的作者是某某，写过……"），让读者建立"它不是凭空冒出来的"的认识。

不要写成学术综述，**一两句点到为止**，长篇大论会破坏节奏。

### ③ 口语化短句，绝不绕弯

- **一句话能说清，绝不用两句**。多用句号，少用长从句。
- 主动句优先（"我们启动服务"），少用被动句（"服务被启动"）。
- 多用"你"、"我们"、"我"作为主语，**像跟朋友聊天，不像念稿**。
- 善用"其实"、"不过"、"顺便说一句"、"说到这里"等过渡词，让行文有节奏感。
- 反例：`该方案通过引入抽象层以解耦核心逻辑与外部依赖，从而提升系统的可维护性与扩展性。`
- 正例：`这个方案就是给核心代码和外部依赖中间加一层。这样以后换数据库，就不用改业务代码了。`

### ④ 生活化类比，复杂概念秒懂

每个抽象概念**必须配一个生活化类比**（阮一峰的招牌手法）。类比的三条原则与写法细则见本文第四节。

### ⑤ 偶尔的"个人观察"，拉近距离

在合适的地方插入一句**作者视角的感悟或小趣闻**，但**点到为止**，不喧宾夺主。

不要每段都加，每章最多 1~2 处。句式参考：

- `"第一次看到这个设计时，我愣了一下，没想到可以这么优雅。"`
- `"老实说，我当初也是踩了坑才搞明白的。"`
- `"这里有个细节，官方文档没明说，但我建议你记住。"`

**禁止**使用鸡汤味、煽情、过度的"我们一定要"之类的话。

### ⑥ 结尾留个"钩子"或"小提醒"

每章结尾不要硬邦邦地"本章小结"，而是用一句**温柔的过渡**引出下一章，或留下一个小提醒。

句式参考：

- `"搞懂了这一点，下一章我们就开始动手写代码。"`
- `"如果你之前没接触过 X，先有个印象就行，下一章会展开。"`
- `"这一节可以跳过，等你用到了再回来看。"`

章末过渡的标准格式（"下一站建议"引用块）见 `tutorial-structure.md`。

## 二、禁用写法清单

为了避免破坏阮一峰风格，**严禁出现**以下表达：

| 类别 | 禁用表达 |
|---|---|
| 学术腔 | `综上所述`、`由此可见`、`总而言之`、`本文将详细介绍` |
| 教材腔 | `作为一个 XXX`、`所谓 XXX 就是` |
| 官腔 | `值得我们注意的是`、`需要特别强调的是` |
| 客套腔 | `本教程将带领大家` |
| 过度口语腔 | `小伙伴们`、`老铁们` |
| 卖课腔 | `非常重要！！！`、`必看！！！` |

另外还禁止：

- 连续超过 60 字无标点的长句。
- 没有具体内容的空泛形容（"非常重要"、"极其强大"、"完美解决方案"）。

## 三、风格自检清单

每章生成完毕后，**逐条对照**：

- [ ] 第一句话是不是"问题"或"为什么"，而不是概念定义？
- [ ] 抽象概念有没有配生活化类比？
- [ ] 每段平均句长是否在 30 字以内？
- [ ] 有没有至少一处"作者视角"的轻量表达？
- [ ] 结尾是不是有自然的过渡，而不是"本章小结"？
- [ ] 是否避免了禁用清单中的所有表达？

> 本文第二节的禁用词，以及 `tutorial-structure.md` 第三节的章末过渡，都可以用 `scripts/check_tutorial.py` 自动扫一遍，不用靠肉眼记。

## 四、类比规范（重点强化）

类比是这套风格里最容易被写成"看起来像、其实不成立"的部分，所以单列一节。

### 1. 三条原则

- **贴**：来自读者熟悉的场景（做饭、搬家、图书馆、银行等）。
- **准**：类比核心机制与原概念一致，不要为了形象牺牲准确。
- **短**：一两句话讲完，不展开。

### 2. 标准格式

每个抽象概念都必须配类比（除非确实找不到合适的）。格式统一为：

```markdown
> **类比理解**：用一两句话讲清楚。
```

### 3. 参考示例

> **类比理解**：数据库索引就像书的目录。你不用翻遍整本书，目录能直接告诉你第几页有答案。

> **类比理解**：容器就像一个独立的房间，镜像就是这个房间的"装修图纸"。

为什么值得较真：读者能记住的往往不是 API 名字，而是那个类比。类比错了，后面所有理解都跟着偏。
