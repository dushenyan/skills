# 语气与展开参考：学阮一峰怎么讲话、什么时候要讲透

> 这是**语气与展开的参考**，不是压缩令。阮一峰的手感好读，但技术教程要**让读者真学会**——该短的短句，该展开的地方要展开到位。内容准确 + 讲透 > 风格漂亮。

阮一峰（[ruanyifeng.com](https://www.ruanyifeng.com)）的教程好读，靠的是几件很朴素的事。写讲解段落时带着这个手感即可。

## 一、上手就能用的五条

1. **先讲痛点，再给方案**。别一上来甩接口列表。"如果你想做 X，但 Y 很麻烦，那 Z 就是干这个的。"
2. **交代一句由来**。这个技术谁做的、为什么做，一两句点到为止，不要写成综述。
3. **句子短一点，用「你」说话**。一句话能说清就别拆成两句；主动语态优先；"其实""不过""顺便说一句"这类词能让行文有呼吸感。
4. **难懂的地方给个类比**。一两句讲完，不要展开成长篇比喻。
5. **结尾留个钩子**，不要"本章小结"。格式见 `tutorial-structure.md` 第四节。

### 类比怎么给

- **贴**：读者熟悉的场景（做饭、搬家、图书馆、快递）。
- **准**：机制真的对得上，不为形象牺牲准确。
- **短**：一两句说完。

```markdown
> **类比理解**：数据库索引就像书的目录，不用翻遍全书就知道答案在第几页。
```

一个概念写不出合适类比，就换个说法或者老老实实解释一遍，不用硬凑。整篇有三五处亮点类比就足够了。

### 关于"作者视角"

偶尔插一句自己的观察，比如"我当初也是踩了坑才搞明白的"，会让文字更近。每章最多一两处，点到为止；不要写成鸡汤。

## 二、什么时候必须展开讲

"短句口语"是**句子的节奏**，不是**内容的深度**。以下四类内容要放开篇幅讲透，不要一句话带过：

| 场景 | 至少给到什么程度 |
|---|---|
| **核心概念 / 学习重点 ⭐** | 定义 → 为什么重要 → 常见用法 2~3 个变体 → 一句话小结；配合代码或示意图 |
| **易踩的坑 / 注意** | 现象 → 原因 → 复现代码 → 修复方案；不要只写"注意 X"就跳过 |
| **常见场景** | 场景描述 → 至少 2 种写法（简单版 + 生产版 / 一次性 + 可复用） → 各自的取舍 |
| **易混淆概念** | 用对比表列维度（性能 / 易用性 / 适用场景 / 生态），表后再写 1~2 段"什么时候选哪个" |

反过来，这些**保持简短**：技术由来、目录导航、"下一站建议"、过渡句、纯装饰性铺垫。

一个可用的判断：**读完这一段，读者能不能独立把它用起来？** 如果不能，就是要展开；如果能，就不要再加"补充说明"凑篇幅。

## 三、容易出戏的表达

下面这些腔调会让读者觉得在看教材，尽量避开。它们基本都意味着"这句话没讲具体"，而不是文风洁癖：

| 类别 | 别用 |
|---|---|
| 学术腔 | 综上所述、由此可见、本文将详细介绍 |
| 教材腔 | 作为一个 XXX、所谓 XXX 就是 |
| 官腔 | 值得我们注意的是、需要特别强调的是 |
| 客套/卖课腔 | 本教程将带领大家、必看！！！ |
| 用力过猛的口语 | 小伙伴们、老铁们 |
| 空话型展开 | "非常重要"、"特别关键"却不给具体用法或例子 |

写的时候顺手避开即可，不用为了这几个词回扫全文。

## 四、想更严格的话

本技能只取语气与展开的分寸感，不追求逐条合规。如果你确实要按阮一峰[《中文技术文档的写作规范》](https://github.com/ruanyf/document-style-guide)对齐文字细节，装 `ruanyf-document-style-guide` 技能。

`scripts/check_tutorial.py` 只兜底机械项（文件命名、代码块闭合、章末指引、学习重点/注意覆盖度），它报出的文字类提示看过一眼就行，不阻断交付。

嫌麻烦的话，交稿前顺一遍这五件事就够了：开头在讲问题吗？重点内容有没有 `> 学习重点 ⭐` 标注？有没有 2~3 个使用变体或场景？有没有一句"我"的观察？结尾自然过渡了吗？
