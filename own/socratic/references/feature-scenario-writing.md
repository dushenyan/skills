# 写作与论证

帮用户打磨论点、论据和逻辑链条。典型入口：「帮我看看这个论点」「这段论证站得住吗」「我想写一篇关于 X 的文章，但思路很乱」。

## 使用

论证场景的核心方法：**给用户的论证画地图**——论点是什么、论据有哪些、中间靠什么推理连接，然后逐段追问最脆弱的一环。

追问重点：

1. **论点澄清**：
   - 「如果整篇文章只能留一句话，你留哪句？那句话就是你的论点。它现在是什么？」
   - 「你的论点是在反驳谁？如果不反对任何东西，它可能只是描述。」
2. **论点-论据映射**：
   - 「这个论据支撑的是主论点，还是某个子论点？把它放到论证树里看。」
   - 「哪一条论据拿掉之后，整个论证会塌？那条是承重墙。」
3. **隐含前提**：
   - 「从『数据 A』走到『结论 B』，你跳过了哪一步？那一步凭什么成立？」
   - 「读者需要先相信什么，才会被你说服？」
4. **反方最强论证（steelman）**：
   - 「一个聪明的反对者会从哪里进攻？把他的进攻写得比你自己的论证还有力，再回头看。」
   - 「有没有人真诚地持有相反观点？他们的理由是什么，蠢还是合理？」
5. **读者视角**：
   - 「你的目标读者是谁？他读到第二段时的第一反应是什么？」

对话示例片段：

> **用户**：我想写一篇文章论证「微服务被高估了」。
>
> **技能**：先澄清靶子：你说的是所有团队都高估了，还是大多数团队在特定条件下高估了？这两种说法需要完全不同的论据。
>
> **用户**：主要是大多数团队其实用不上。
>
> **技能**：`> 我听到的是：论点其实是「适用门槛比想象的高」，而不是「技术本身不好」。` 那一个聪明的反对者会说：失败案例是执行问题，不是选型问题。你打算怎么回应这一击？

## 要点

- 先帮用户把论点压成一句话，再谈论据。论点模糊的论证没法修。
- steelman 永远问「最强的反对」，不问「最蠢的反对」。打稻草人没有训练价值。
- 论证链条画出来后，追问承重墙论据，不平均用力。
- 用户写的是学术论文时，追问的落点常在「贡献声明」和「威胁有效性（threats to validity）」。
