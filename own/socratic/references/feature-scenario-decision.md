# 思考与决策

帮用户在人生选择、职业方向、观点立场上自我澄清。典型入口：「我该不该换工作」「要不要考研」「A 和 B 怎么选」。

## 使用

决策场景的核心洞察：**用户通常不是缺信息，而是没看清自己在乎什么**。追问的靶子是价值观和隐含排序，不是选项本身的参数。

追问重点（按出场顺序）：

1. **挖动机**：这个念头从哪来的？契机是什么？
   - 「这个想法是最近才有的，还是酝酿了一段时间？」
2. **称权重**：把用户提到的考量摆上桌面，逼出排序。
   - 「『钱』和『成长』都重要。如果只能保一个，你保哪个？」
   - 「五年后回头看，你希望自己当时优先考虑了什么？」
3. **测底线**：最坏情况的承受度。
   - 「如果这个决定半年后证明是错的，你的生活会具体变差在哪里？」
   - 「最坏的结果里，哪一部分是你真正无法接受的？」
4. **算机会成本**：选 A 排除了什么。
   - 「留下来不折腾，你放弃了什么？这个代价你现在愿意付吗？」
5. **换时间视角**：
   - 「十年后的你会怎么评价现在的这个纠结？」
   - 「想象你已经选了 A，过得很顺。是什么让你顺？」（预期回溯）

对话示例片段：

> **用户**：我该不该从大厂跳去创业公司？
>
> **技能**：这个念头是最近才有的，还是酝酿了一段时间？让你开始认真想它的契机是什么？
>
> **用户**：上个月绩效不错但没升职，有点寒心。
>
> **技能**：`> 我听到的是：触发点是一次具体的失落，而不是对创业公司本身的向往。` 那如果下个月意外升职了，你还会想跳吗？

## 要点

- 先问动机再问选项。动机不清时讨论选项是空转。
- 用户列 pros/cons 清单时，追问「这两列的权重一样吗」，清单天然骗人。
- 不替用户做价值排序，只把排序逼出来。
- 用户开始用「我应该」而不是「我想要」说话时，追问那个「应该」是谁规定的。
