# 无用信息清单

收集型初稿的噪音来源，按命中频率排列。

## 一、对话残留（最常见）

AI 对话或聊天截图转写来的稿子，尾部常挂着服务式句子：

- 「接下来你更想看 A，还是 B？」——引导语，删。
- 「直接给结论：」「希望对你有帮助」——客服腔，删。
- 「这段不是报错，是软件在提醒你……」——把元评论改写成正常解释句，信息（这是告警不是错误）保留，形态（对话感）删掉。

## 二、重复内容

同一条命令、同一套步骤在稿内出现两次以上时，合并到逻辑上最合适的一节，其余位置用一句话指路（「见第 X 节」）。合并时逐字段对比，两次表述若有信息差（一次多讲了参数、一次多了警告），取并集，不取先出现的版本。

## 三、跑题对比

「顺便聊聊其他工具」的展开段落，若与本篇主线无关，压缩成一张表或一两句，或者整段移到文末附录。判断标准：读者照本篇操作时是否需要这段？不需要就不配占正文篇幅。

## 四、无信息量修饰

- 「极其强大」「完美解决」「非常重要」——空泛形容，删或换成具体数据。
- 「值得一提的是」「需要指出的是」——填充语，删，直接说事。

## 删除底线

以下六类内容，无论藏在多糟糕的句子里都不能删：

1. 事实与数字（版本号、延迟、容量、路径）。
2. 否定与警告（「不打开会失效」「会黑屏」）。
3. 条件与时间（「先 USB 连一次」「重启后」）。
4. 归因（「这是系统限制不是软件问题」）。
5. 图片引用本身——删段落可以，图要挪到对应位置，不能凭空消失。
6. 「【（xxx）】」包裹的用户本人的话——不但不能删，还要重点理解意图、扩写成正式正文。摘取的其他材料才可大幅改造。
