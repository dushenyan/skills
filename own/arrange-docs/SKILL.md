# Arrange Docs

收集来的初稿通常有三个通病：对话残留混在正文里、图片和文字各说各话、同一内容散落在多处。这个技能把「收集材料」变成「能发出去的文档」，五步走完。

## 核心参考

| 主题 | 描述 | 参考 |
|-------|-------------|-----------|
| 删除无用信息 | 对话残留、重复内容、跑题对比的识别清单与删除底线 | [core-cleanup](references/core-cleanup.md) |

外部依赖（一律复用现有技能，不自造规则）：排版与叙事用 `ruanyf-document-style-guide`，去 AI 味用 `humanizer-zh`。

## 工作流

### 1. 通读诊断

先完整读一遍原文，列出三类问题：哪些是对话残留、哪些内容重复、图片是否真实存在（Glob 核对引用路径）。缺图先告知用户，不凭空编造图片内容。

同时分辨内容的来源：**被「【（xxx）】」包裹的是用户本人的话**（需求、想法、待写提示），其余都是从别处摘取的材料。这个区分决定后面的改造尺度。

**示例**：初稿里出现 `【（这边需要介绍 Github 中获取令牌的方式）】`，「这边需要介绍 Github 中获取令牌的方式」要重点解读——它不是占位噪音，而是一条写作指令：此处应新增一节，讲清在 GitHub 上创建并获取 personal access token 的步骤。改写时按此意图编写正文，解读出的操作路径、名称等具体事实需来自可查证的来源，不凭想象编造。

### 2. 删除无用信息

对照 [core-cleanup](references/core-cleanup.md) 的清单删。底线一条：**删形态，不删信息**。事实、数字、条件、否定、警告，无论包在多难看的句子里，都要活下来。

### 3. 图文对应

初稿里的图片往往只有一句「如图所示」。要做的：

- 用 Read 逐张查看每张图，读出图里的命令、输出、设备型号、关键数值。
- 把图移到它真正对应的步骤处，而不是堆在文末。
- alt 文本写成独立图注：「这张图是什么 + 图里最关键的 1-2 个信息」，读者不看正文也能明白。
- 图里有需要解释的异常输出（警告、报错），在正文补一句这是否影响使用。

### 4. 重组与风格化

- **优先展开「【（xxx）】」。** 这是用户自己的话，必须重点理解其意图，编写成正式的正文内容——占位的话要长成段落，提要求的话要落实成对应章节。展开只沿着原意图写，不虚构用户没表达的观点。
- **摘取材料可大幅改造。** 结构、顺序、措辞、详略都服从成文需要，但事实、数字、警告照搬不改（见 core-cleanup 删除底线）。
- 章节按读者的操作顺序或认知顺序重排（准备 → 安装 → 使用 → 进阶 → 限制），重复内容合并到一处。
- 排版与叙事加载 `ruanyf-document-style-guide` 技能执行：中英文空格、全角标点、数值半角、短句、问题驱动开头、按需类比。
- 已有文档补 front-matter（id/title/createTime），缺失字段用 `uuidgen` 与 `date` 生成，不手编。

### 5. 去 AI 味（交付前必做）

这不是可跳过的附录。定稿前先跑扫描，再对照判定标准逐条过，两条都过才算交付。

`humanizer-zh` 在仓库里位于 `external/`，安装到编辑器后与其他技能平铺在同一 `skills/` 下，相对路径随布局变化。先定位脚本再跑，两种布局都覆盖：

```bash
SCAN=$(ls ../humanizer-zh/scripts/scan-ai-tone.mjs ../../external/humanizer-zh/scripts/scan-ai-tone.mjs 2>/dev/null | head -1)

node "$SCAN" 文档.md   # 文档已落盘
node "$SCAN" -         # 从标准输入读
```

扫描只负责把候选捞出来，判定标准在 `humanizer-zh/SKILL.md` 的 A–F 检查点（仓库内为 `external/humanizer-zh/SKILL.md`）。命中不等于必须改，承载实际信息的句子照原样保留，但每处「保留」要在交付报告里给出理由。

## 输出要求

- 修改写回原文件，不新建副本，除非用户点名要。
- 交付报告分三块：删了什么（含删除理由）、图片如何对应、润色与去 AI 味的命中项和通过项。
- 对「检查过但故意没改」的表达，报告里给一句理由，避免用户误以为是遗漏。
