# SKILL.md 正文编排风格

本文件定义**正文怎么写**，与 `core-description`（描述怎么写）、`core-checklist`（检查什么）互补。适用于工作流型、编排型技能；纯参考型技能按需取用，不强制套全部章节。

风格样本：`external/baoyu-image-gen/SKILL.md`（上游技能，原样保留，本文件提炼其可读处）。

## 六个特征

| 特征 | 做法 | 反例 |
|------|------|------|
| 表格化密集信息 | 并列选项、分流条件、节点状态、参数清单一律上表 | 用长段落罗列「如果……就……否则……」 |
| 编号规则 | 工具选择、优先级、硬约束用 `1. 2. 3.`，每条一句祈使 | 把三条规则揉进一个段落 |
| 阻断标注 | 需要暂停等用户的节点，标题或句首标 `(blocking)` / `（阻断节点）` | 「问完继续」写在末尾，读者以为可以自己往下做 |
| Step 编号标题 | 顺序流程用 `## Step N: 名称`，不用「一、二、三」混排 | 同一文件里「Step 1」和「检查点一」并存 |
| first hit wins | 多条件分流写明优先级，命中第一条就停 | 三个条件都像「可以走」，执行时反复横跳 |
| 规则只说一次 | 全局规则写一处，后面只引用；不在各节重复措辞 | 同一句「暂停等用户」出现三次、措辞还不一致 |

## 话术一致性检查

同一概念在全文只用一个词。改造时先列出易分裂的词，统一后再落笔：

| 概念 | 统一用词 | 不要混用 |
|------|---------|---------|
| 用户确认节点 | 阻断节点 / 交点 | 检查点一、二 / 通用检查点 / 交点混着叫 |
| 暂停行为 | 弹窗后暂停，等用户答 | 这一轮就停 / 问完继续 / 停下来等 |
| 路线入口 | 转入「X」节点 N | 进入通用检查点 / 走下一步 |

## 什么时候不套

- 技能只有一份硬规则清单（如排版规范）：保持列表，不强行 Step 化。
- 纯资料型参考：表格与编号按信息本身决定，不为风格而风格。
- 用户已指定文件格式或沿用项目约定：以用户/项目为准。

## 诊断时的用法

在「风格与命名」维度里检查这六项；发现混用术语、规则重复、长段落罗列条件时，按本文件给建议修法。不改动技能的技术判断，只动结构与表述。
