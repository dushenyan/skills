# 模糊需求澄清器

用户经常甩来一句话需求：「帮我写个博客」「做个记账工具」。本技能在这种情况下先不执行，而是用最少的提问把需求问清，输出一张**问题重述卡片**，确认后直接开工。为执行服务，不是陪聊。

## 核心工作流

```
第 0 步 · 触发判断    需求缺关键项才启动，具体的需求直接开工
第 1 步 · 框定        1～2 个开放问题，识别任务类型和真实意图
第 2 步 · 补缺        按缺口清单用带选项的问题批量补齐
第 3 步 · 重述开工    输出重述卡片 → 用户确认 → 直接执行
```

### 第 0 步 · 触发判断

需求缺以下任意一项，才进入澄清流程：

- **对象**：给谁看 / 给谁用？
- **目标**：做完之后什么东西变好了？
- **产出形态**：文章、代码、清单、方案，还是别的？

三项都齐，直接开工，一步都不要问。过度提问比不问更烦人。

### 第 1 步 · 框定

用 1～2 个开放问题识别任务类型和意图：

- 「你想拿它做什么用？」
- 「想象它做完了，你在什么场景下用到它？」

任务类型四分（决定第 2 步用哪份缺口清单）：**写东西、做东西（代码）、做决定、学东西**。

### 第 2 步 · 补缺

按 [core-gap-checklist](references/core-gap-checklist.md) 里对应任务类型的清单，找还没答案的维度，用带选项的问题批量补齐。提问方式见 [feature-question-patterns](references/feature-question-patterns.md)。

原则：只问缺口，用户已经说清楚的绝不重复问。

### 第 3 步 · 重述开工

输出问题重述卡片（模板见 [feature-restatement](references/feature-restatement.md)），固定五块：**目标、边界（做什么 / 不做什么）、关键参数、成功标准、假设标注**。「假设标注」是没问出来、替用户定的默认值清单，用户可逐条推翻。

用户确认（或修正后确认）→ 同一会话直接开工，执行时不再重复确认。

## 硬规则

1. **总开销 ≤3 轮、问题总数 ≤6**。到顶了就带着标注的假设开工。
2. 选择题必须给「帮我定」出口，用户选了就用默认值。
3. 用户说「直接做」「你看着办」→ 跳过剩余提问，立即带假设开工。
4. 用户表现出不耐烦（连续短回复、反问「你觉得呢」）→ 下一轮直接给重述卡片。
5. 重述卡片里的假设要单独成块，不许混进确定的信息里。

## 语言规范

所有提问和重述卡片对齐 ruanyf-document-style-guide 技能的规范（按技能名加载）：全角标点、中英文之间加半角空格、短句、无空泛形容词。

## 示例

**用户**：帮我写个博客。

**技能行为**：
1. 第 0 步：对象、目标、形态全缺，启动澄清。
2. 第 1 步框定：「想象这篇博客发出去之后，你希望谁在读它？读完他记住什么？」
3. 用户回答后判定为「写东西」，第 2 步按缺口清单用选择题补齐：体量、读者水平、风格基调、发在哪、要不要配代码示例，每个都带「帮我定」。
4. 第 3 步输出重述卡片，假设标注（如「默认读者：懂一点编程的新手」），确认后直接开写。
