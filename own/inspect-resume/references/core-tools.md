# 核心求职诊断工具

7 个工具串成一条求职流水线：**定位 → 简历 → 策略 → 外联 → 面试 → 复盘**。每个工具都给出「面试官凭什么判断」的标准，而不只是名字。

> 边界：本文件只做**诊断与判定**。把项目素材改写成分档简历要点、组织 STAR 故事由 `project-highlights-extractor` 技能负责，需要时交叉引用，不在此重复 bullet 句式规范。

---

## 1. 零回复诊断

**用途**：投了一批却没面试回执时，定位卡在漏斗的哪一层。

技术简历投递的真实漏斗（每层淘汰原因不同）：

```
ATS/关键词粗筛 → 招聘官 6~10 秒初筛 → 用人经理细看 → 约面
   (没进人才库)     (扫到红线直接刷)     (岗位匹配度)    (作品集/背景调查)
```

逐层排查清单：

| 层 | 面试官实际在看什么 | 典型失分 |
|----|--------------------|----------|
| ATS 粗筛 | 是否命中 JD 硬技能关键词、职级/年限、学历门槛 | 技术栈只写「熟悉后端」不给具体框架名；缺 JD 里的硬性关键词 |
| 6~10 秒初筛 | 近两段经历的 title/公司/时间是否连贯；有没有可量化产出；行数与信息密度 | 时间空窗无解释、title 与投递岗位落差大、通篇职责无数字 |
| 用人经理细看 | 项目技术难度是否匹配团队在做的事、深度能否撑起描述 | 技术名词堆砌却讲不出选型理由（面试也会露馅，宁可前期收敛） |
| 约面 | 地点/远程/薪资预期是否冲突；背景是否有硬伤 | 薪资区间超出岗位带、地点不可达 |

**输出**：一张诊断卡——卡在哪一层（至多两层主因）+ 每层的**具体证据行**（引用原简历）+ 对应修复动作。修复若涉及改写要点，转 `project-highlights-extractor`。

**红线清单**（任一命中，先看这里）：技术栈与投递岗位方向不符；核心经历全是「参与/协助」无独立产出；时间线断裂且无说明；明显夸大（写了答不出的框架）。

## 2. 目标职位锚定

**用途**：背景杂、方向飘时，收敛到 1 条主赛道 + 1 条备选。

技术岗定位三维打分（各 1~5 分，取交集最高项）：

- **技术栈深度**：哪套栈你答得出选型理由和踩坑细节（不是「用过」）。
- **业务域连贯**：过去经历集中在哪个领域（如交易/内容/基础设施/AI）。
- **职级现实**：按年限 + 独立负责过的模块规模，落在初/中/高级的哪一档。

**流程**：用户给背景 → 三维打分 → 剔除「听起来光鲜但答不住」的方向 → 输出主赛道 + 备选，各配：目标 title、对标 JD 关键词 3~5 个、需要补强的一项能力。

聚焦原则：宁可一条赛道打透，不要在 4 个方向各投 5 份。

## 3. 应聘策略系统

**用途**：把「海投」变成可追踪、可调参的投放系统。

要素：

- **渠道配比**（技术岗）：内推 / 招聘平台直投 / 目标团队 GitHub·博客·会议露脸 / cold outreach。早期内推占比最高，转化率约为直投的 4~8 倍。
- **简历定制节奏**：按主赛道维护 1 份母版 + 按 JD 关键词微调的投递版；不逐份重写，改「关键词与要点排序」即可（排序与关键词适配交给 `project-highlights-extractor`）。
- **进度追踪表**：

  | 公司 | 岗位 | 渠道 | 投递日 | 回执 | 阶段 | 复盘标签 |
  |------|------|------|--------|------|------|----------|

- **健康指标基准**（低于则回查第 1 个工具）：直投回复率 ~5-10%、内推 ~25-40%；到面后通过率 <20% 说明面试环节（工具 6）是瓶颈而非简历。

**输出**：一周期的投放计划（投多少、走哪些渠道、如何追踪、何时复盘）。

## 4. 招聘官视角重写

**用途**：模拟 6~10 秒初筛，找出会被一眼刷掉的点并排序修复优先级。

视线落点（F-pattern，按扫描顺序）：

1. name + 当前 title + 当前公司/时间（判断「是不是我们要的人」）
2. 最近一段经历的 2~3 行（判断「有没有硬产出」）
3. 技术栈/技能栏（判断「关键词对不对得上 JD」）
4. 教育/年限（判断「有没有硬门槛问题」）

**通过 / 淘汰判定标准**：

- 通过：10 秒内能答出「你是谁、做过什么有分量的事、和我岗位相关在哪」。
- 淘汰：亮点埋在第二页；技术栈与 JD 无交集；通篇职责无数字；信息密度过低（大量空白/图形）。

> 本工具只做**初筛诊断 + 修复优先级排序**。具体每条 bullet 怎么改成「动作+手段+量化结果」不在这里展开，转 `project-highlights-extractor`。

**输出**：亮点/盲区清单（标注视线落点位置）+ 按「投入产出比」排序的 3 条优先修复项。

## 5. 冷邮件生成器

**用途**：直投无回执或想触达目标团队时，写一封对方愿意回的 outreach。

技术岗 cold outreach 骨架（正文 ≤120 字，一屏读完）：

```
主题：<具体价值锚点> - <你的差异化标签>
  例：「Milvus 召回延迟优化经验，想聊聊你们的检索岗」

正文：
1. 钩子（1 句）：点出对方的具体情境（某产品/某篇文章/某岗位），证明不是群发。
2. 价值（1~2 句）：我最相关的一段硬产出，带一个数字。
3. 行动（1 句）：低门槛请求——「方便的话 15 分钟请教」，而非「给我个工作」。
```

差异化钩子优先级：针对该团队技术栈的真实问题/改进点 > 引用对方公开内容 > 泛泛仰慕。

禁忌：附件塞满、长篇自我介绍、群发口吻（「贵司」「诚聘」）、一上来要内推码。

**输出**：1 封主邮件 + 2 个变体（更短 / 更强的技术钩子）。

## 6. 面试模拟器

**用途**：扮演目标职位的技术招聘经理，做全真模拟并给出**评分与改进**。这是本技能价值最高的工具。

**流程**：

1. 用户给目标职位（title + 技术栈 + 职级）。
2. 按下方题型组合出题，一题一问、答完追问，模拟真实节奏。
3. 每个回答给即时反馈：判分 + 缺哪层 + 怎么补。

**提问分类**（技术岗典型配比）：

| 类型 | 面试官在验证什么 | 代表问题 |
|------|------------------|----------|
| 项目深挖 | 简历写的真是你做的吗、理解到哪一层 | 「你这个方案为什么选 X 不选 Y？上线后遇到什么问题？」 |
| 技术基础 | 基本功是否扎实 | 语言特性、数据结构、并发、数据库/网络原理 |
| 系统设计 | 权衡与结构化思维（中高级必考） | 「设计一个短链接服务，读写比 100:1」 |
| 行为/协作 | 冲突处理、主动性、复盘能力 | 「讲一次你和同事的技术分歧，怎么收敛的」 |
| 动机/匹配 | 为什么是你、为什么是这个岗位 | 「为什么离开现在团队？对我们的业务了解多少？」 |

**下钻打法（面试官怎么判断深度）**：顺着每个答案追到 L5——

```
L1 你做了什么 → L2 为什么这么做 → L3 考虑过哪些替代方案 →
L4 有什么权衡/代价 → L5 再做一次会怎么改 / 边界在哪
```

答到 L2 就空 = 「只会执行」；能到 L4/L5 = 「有判断力」，这是初级与资深的分水岭。

**评分量表**（每题 1~5，反馈时给出）：

| 分 | 表现 |
|----|------|
| 1 | 答非所问 / 概念错误 / 明显编造 |
| 2 | 知道名词但讲不清原理与场景 |
| 3 | 原理正确、能举一例，缺权衡 |
| 4 | 有取舍、能对比替代方案、结合过真实项目 |
| 5 | 结构化 + 深度 + 主动延展边界条件与失败场景 |

**被判「没深度」的信号**：只描述「做了什么」不说「为什么」；用「大家都这么写」当理由；被追问替代方案时卡壳；数字张口就来但答不出测算口径。

**行为题**用 STAR 组织回答（写法见 `project-highlights-extractor`），这里负责**提问 + 判分 + 追问**。

**输出**：逐题「问题 → 你的回答要点 → 判分 → 缺失层 → 改进版示范」，结尾给整体评级与最该补的 1~2 项。

## 7. 求职全案审计

**用途**：投递一段时间（如 2~4 周）后系统性复盘，定位整体瓶颈。

四维体检（各给「现状 / 瓶颈 / 优化动作」）：

| 维度 | 审计问题 | 数据信号 |
|------|----------|----------|
| 简历 | 是否过得了初筛 | 回复率 vs 工具 3 基准 |
| 定位 | 赛道是否收敛 | 是否同时投了方向不符的岗位 |
| 外联 | 触达方式是否有效 | 内推占比、cold 回复率 |
| 面试 | 到面后为何不通过 | 挂在第几轮、哪类题型低分（用工具 6 评分） |

**输出**：一张全案记分卡 + 按「对最终 offer 影响大小」排序的优化清单（至多 5 条），每条指明用哪个工具落地。
