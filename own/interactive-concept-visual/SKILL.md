# 交互式概念可视化

用一页单文件 HTML，让初学者在几分钟内亲手操作，看见一个概念怎么运作、为什么这样设计。


## 开工前先定三件事

1. 读者是谁。默认初学者：不熟术语，需要一个能对上日常经验的锚点。
2. 概念的核心难点是什么。差异、顺序、结构、参数、状态，还是纯粹抽象？这决定形态。
3. 这页只讲什么。一件事讲透，胜过三件事各讲一半；讲不完就拆页。

## 形态按难点选

| 难点 | 候选形态 | 关键动作 |
|---|---|---|
| 几个方案哪里不同 | 并排分栏、左右分屏、开关切换 | 同一输入分别跑，让分歧可见 |
| 分几步发生 | 横向流程、步骤条、时间轴 | 单步前进，当前阶段高亮 |
| 由哪些层组成 | 嵌套图、树、分层卡片 | 点节点展开，配一句人话 |
| 参数改变结果 | 滑杆、输入框 + 实时输出 | 拖动即更新，保留上一次的值做对照 |
| 状态怎么迁移 | 状态图、可点击节点 | 点状态看下一步允许去哪 |
| 太抽象、难想象 | 生活化类比 + 数据映射 | 类比之后明确指出它哪里不准确 |

形态可以混用，但每个模块都要服务同一个问题。选完自检一次：去掉所有装饰后，这页是否仍在回答同一个问题？答不上来就删模块。

## 让初学者真的看懂

- 先例子后定义：用具体场景开场，读者看见现象之后再引入术语。
- 过程可见：把中间状态画出来，形状、层级、流向、中间值都算，不能只给结论数字。
- 可动手：至少有一个控件能让读者改条件、看结果；纯滚动阅读不算交互。
- 反馈即时：操作后图形、数字、文案一起变，并且能看出变了多少。
- 结论由数据生成：文案跟着当前状态走，不要写死。
- 类比标边界：用生活化比喻降低门槛，同时说明它在哪不成立。
- 数字标来源：示意值注明示意，实测值给出条件。

## 设计基线

- 颜色、字体、间距全部走 CSS 变量；深色打底，浅色只覆盖变量。
- 浅色不是反色：强调色单独调深，半透明前景色系统性地换成墨色透明度。
- 字体用系统已有的三档：衬线标题、无衬线正文、等宽标注，不引外部字体与图标。
- 全页只用两个强调色，各自绑定一种方案、路径或状态。
- 背景给轻微光晕或纹理，卡片用细边框配低透明度表面色，避免纯色铺底与重阴影。
- 紧凑是默认且唯一的布局：信息密度优先，窄屏自动单列；字号与间距按这一页的内容现场定。
- 动效只服务理解，时长以看得见但不拖沓为准；`prefers-reduced-motion` 时全部关闭。

## 实现要点

- 单文件，无 CDN、无外链图片，双击 `file://` 可开。
- 内容与视图分离：数据放数组或对象，渲染函数生成 DOM，换内容不动结构。
- 主题在 `<head>` 内先定再绘制，选择存 `localStorage`，避免刷新闪色。
- 需要过渡的元素，先渲染初始值，下一帧再设目标值。
- 需要随机或波动效果时用固定种子，保证同一输入每次结果一致。
- 可交互元素补状态属性与 `:focus-visible`；动态结果区用 `aria-live`。
- 不把颜色当作唯一信息载体，配文字或形状标签。

## 交付前检查

- 结构闭合，脚本可解析（`node --check`）。
- 起本地服务打开（浏览器工具不支持 `file://`），在深/浅 × 宽/窄四种组合下无横向滚动、无重叠、控件不压内容。
- 每个控件都真实可操作，反馈与文案同步。
- 刷新后主题保持，且没有闪色。

## 常见坑

- 颜色值硬编码，浅色主题下发灰发脏。
- 固定定位的控件压住页头，任何尺寸调整后都要重新量。
- 文案写死，状态一变就自相矛盾。
- 过渡不触发，因为 DOM 建好直接写了终值。
- 演示数据体现不出差异，页面看着热闹却没有信息量。
- 引外部字体或图标，离线退化甚至白屏。

## 终检：去 AI 味（流程的最后一步）

定稿前按 `humanizer-final-check` 技能跑终检（扫描脚本定位 + 六条清单 + A–F 判定），两层都过才算交付。

## 达标标准

初学者看完能否用一句话说出「它是什么、为什么需要它」；每个交互是否都带来可见变化；去掉装饰后信息是否仍然成立。三项都过，才算完成。
