# 结构骨架（按论文类型选）

> 结构是为了讲清内容，不是为了填满模板。**先判断论文属于哪一类，再选骨架**；用户指定了章节就直接照用户的，不套任何骨架。每套骨架都可以砍章、加章、重排编号，不留空章、不跳号。
>
> 可复制模板（骨架 A + 三种非文章型产物）见 [feature-article-template](feature-article-template.md)。

| 论文类型 | 怎么认 | 推荐骨架 |
|---|---|---|
| 架构 / 方法创新型（提出新模型、新机制） | 有明确的核心贡献模块，常带公式与架构图 | 骨架 A（下方八段式，默认） |
| 实验实证型（验证某个假设 / 评测某个做法） | 主体是实验设计、对比与消融，没有新架构 | 骨架 B |
| 理论证明型（定理、收敛性、复杂度） | 核心是定理陈述与证明链 | 骨架 C |
| 综述 / survey | 没有单一核心贡献，按分类梳理整个领域 | 骨架 D |
| 工程博客 / 技术长文（无公式） | 官方博客、实践总结、方法论文章 | 骨架 E |
| 数据集 / 基准型 | 核心资产是数据集或评测基准 | 骨架 F |

### 骨架 A：架构 / 方法创新型（默认）

| 章节 | 作用 | 必备 |
|---|---|---|
| 元信息块 | 原文链接、作者、发表、地位 | 是 |
| 一、先搞清楚：它在 XX 史上是什么位置？ | 类比开场，讲前史与颠覆点 | 是 |
| 二、这篇论文要解决什么问题？ | 背景 + 主流方案的缺陷 | 是 |
| 三、核心概念逐个拆解 | 全文主体，概念 + 公式 + 类比 | 是 |
| 四、拼装完整架构/机制 | 把零件组装成整体 | 视情况 |
| 五、为什么它赢了？ | 对比论证（表格对比） | 视情况 |
| 六、训练/工程/实现细节 | 让方案落地的参数与取舍 | 视情况 |
| 七、实验结果 | 用数据说话（表格） | 视情况 |
| 八、总结与回望 + 5 个要点 | 意义与影响 | 是 |

各章的写法要点：

**元信息块**：见 SKILL.md 第三章第 2 节。后面直接接 `---` 与正文分隔。

**一、先搞清楚：它在 XX 史上是什么位置？**
- 用一句话类比点出“旧的做事方式”及其硬伤，再点出“它改成了什么”；类比按 [feature-narrative-rules](feature-narrative-rules.md) 的构造法现做。
- 标题里带上领域名，如“这篇论文在 AI 史上是什么位置？”（换成任何领域同理）

**二、要解决什么问题？**
- 先讲当时的主流方案，再讲它的硬伤。方案通常有 2～3 个，每个一小节。
- 原文的痛点陈述用引用块 + “翻译成人话”。

**三、核心概念逐个拆解**
- 这是最花力气的一章。一个概念一个小节。
- 每个概念：**痛点 → 直觉/类比 → 定义 → 公式（如有）→ 逐块解释**。
- 容易被忽略但精妙的设计，单独拎出来讲（任何领域都有等价物——示例“为什么除以 √dk”只是演示什么叫“容易被忽略的精妙”，按论文现挑）。

**五、为什么它赢了？**
- 用对比表格。表头加粗，表格后必须有一段文字总结。
- 挑 2～3 个能分出高下的维度（示例中的“计算复杂度 / 顺序操作数 / 最大路径长度”只是演示挑法），维度按论文真正的争论点现挑。

**六、训练/工程/实现细节**
- 挑对读者有用的参数讲（数据集、硬件、学习率、正则化）。
- 每个参数都要解释“为什么这么设”。

**七、实验结果**
- 用表格列关键指标，表格后给 2～3 条硬核结论（质量如何、成本如何）。

**八、总结与回望 + 5 个要点**
- 先引用论文自己的结论，再讲“今天回头看，它的意义远超论文本身”，给 3～4 条影响。
- 最后用小节标题“记不住全部？只需要记住这 5 个要点”，编号列表收尾。

### 骨架 B：实验实证型

| 章节 | 作用 |
|---|---|
| 元信息块 | 同上 |
| 一、这个假设从哪来 | 问题背景 + 已有结论的矛盾或空白 |
| 二、怎么验证 | 实验设计：变量、对照组、数据集、指标 |
| 三、结果说了什么 | 主结果表 + 消融 + 误差分析 |
| 四、怎么解释 | 与假设对照：成立 / 部分成立 / 不成立 |
| 五、边界在哪 | 适用条件、失效场景、未解释现象 |
| 六、对我们的启示 | 可迁移的结论 + 5 点清单（可选） |

### 骨架 C：理论证明型

| 章节 | 作用 |
|---|---|
| 元信息块 | 同上 |
| 一、问题怎么形式化 | 符号、假设、目标 |
| 二、主定理在说什么 | 先用人话陈述，再给原式 |
| 三、证明思路 | 分步骨架，每步一句直觉 |
| 四、关键引理 | 只讲最吃劲的两三条，其余列清单 |
| 五、这个界紧不紧 | 与已有结果的对比、反例或下界 |
| 六、适用边界与意义 | 假设的代价 + 后续影响 |

理论型论文里，**人话陈述**比公式更重要：读者先要知道定理在说什么，才愿意看证明。

### 骨架 D：综述 / survey

| 章节 | 作用 |
|---|---|
| 元信息块 | 同上 |
| 一、领域全景 | 用一张分类图或分类表立骨架 |
| 二、每一类方法 | 各类的典型做法、代表工作、优缺点 |
| 三、横向对比 | 统一维度的大表（能力 / 成本 / 数据需求 / 适用场景） |
| 四、演化脉络 | 时间线：方法是怎么一步步变过来的 |
| 五、空白与趋势 | 作者指出的 open problems + 自己的判断 |
| 六、选型建议 | 什么场景选哪类（必写） |

综述的读者不是要“读懂一篇论文”，而是要有**判断力**。所以最终要落到选型建议。

### 骨架 E：工程博客 / 技术长文

| 章节 | 作用 |
|---|---|
| 元信息块 | 同上（发表一栏写“官方工程博客 + 日期”） |
| 一、他们遇到了什么问题 | 真实场景 + 旧做法的代价 |
| 二、试过哪些方案 | 至少两个失败或次优方案，讲清为什么不行 |
| 三、最后怎么做 | 方案 + 关键取舍 |
| 四、效果与代价 | 数据 + 没解决的遗留问题 |
| 五、什么情况下别照抄 | 适用边界（这一章最能体现判断力） |
| 六、要点清单 | 5 条以内（可选） |

### 骨架 F：数据集 / 基准型

| 章节 | 作用 |
|---|---|
| 元信息块 | 同上 |
| 一、为什么还要一个新数据集 | 已有数据集缺什么 |
| 二、怎么造出来的 | 采集、清洗、标注流程与质量控制 |
| 三、数据长什么样 | 规模、分布、字段、示例 |
| 四、基线跑分 | 表：各模型在该基准上的成绩 |
| 五、怎么用、别怎么用 | 评测协议、常见误用 |
| 六、已知偏差 | 覆盖盲区与伦理问题 |

非文章型产物（一页纸摘要、精读笔记、汇报稿、多篇对比综述）不套上述骨架，模板见 [feature-article-template](feature-article-template.md)。
