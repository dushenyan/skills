# 示例对话

三个典型场景的行为示范。看不清楚某一步该做什么时，回来对照这里。示例中的具体论文（agents 博客、ColBERT）只用于演示流程——处理 RFC、官方文档、教材章节等任何材料时，步骤完全相同。

## 示例 1：默认解读文章

**用户**：解读一下这篇论文 https://www.anthropic.com/engineering/building-effective-agents

**Skill 行为**：
1. WebFetch 抓取全文，确认作者、发布日期、全部章节与小节。
2. 提炼核心主张：最成功的实现用的是简单可组合的模式，而非复杂框架。
3. 定"地位"：把"何时该用 agent、何时不该用"讲清楚的一篇纲领性文章。
4. 以八段式规划章节：把 5 种工作流各立一节，附录的 ACI 设计单独成章。
5. 为每个概念配类比（工作流像流水线、agent 像能自己拿主意的员工、ACI 像给新同事写接口文档）。
6. 逐章撰写，公式/原文引用按规范处理。
7. 结尾给"记不住全部？记住这 5 点"。
8. 保存为 `technicals/Papers/Building Effective Agents 解读.md`。
9. 对话收尾：一句话汇报文件路径，附编号问题选项（深入某章 / 调整讲法 / 检查公式显示 / 解读下一篇）。

## 示例 2：模糊表述，先 clarify

**用户**：语义检索是什么时候？

**Skill 行为**：
1. 第 0 步：这是一句模糊表述，没有具体论文——先调用 `clarify` 技能澄清。
2. 澄清后确认：用户想读的其实是某篇具体论文（如 ColBERT），读者是懂一点编程的新手。
3. 拿到确认的重述卡片后，回到本技能第 1 步，按正常流程抓全文、写解读。

## 示例 3：非默认任务（一页纸摘要卡片）

**用户**：这篇论文我下午要开会，给我一页纸摘要，别写成长文。

**Skill 行为**：

0. **任务画像**：任务类型＝一页纸摘要 → 走模板 B；篇幅＝一屏读完；语气＝工程简报，不用阮一峰式类比；公式＝只提结论；落位＝默认 `technicals/Papers/<标题> 摘要.md`。
1. 抓全文，只取摘要、方法主脉络、主结果表、结论与局限。
2. 按模板 B 写：一句话概括 + 解决什么问题 + 做法 3 条 + 结果对比表 + 适合/不适合 + 3 个要点。
3. 不写长引言，不做逐章拆解，不硬塞类比。
4. 自检：一屏读完、有数字、适合与不适合都写了。
5. 交付：一句话汇报 + 编号选项（展开成完整解读 / 再压到 5 行 / 改成汇报稿 / 对比同类论文）。
