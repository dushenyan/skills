# 图片生成方案设计

图片分两类，提示词结构不一样：

- **表达型**：摄影、插画、3D 渲染、主视觉、产品图、封面。靠画面本身说话，重点在主体、光线、材质、情绪。
- **信息型**：信息图、架构图、流程图、对比图、时间轴。靠结构承载信息，重点在分区、层级、标注。

先判断属于哪类，再选骨架。把信息图那套「分区 + 层级」硬套到人像上，只会得到一张呆板的图；反过来把摄影那套「光影 + 氛围」套到架构图上，也讲不清结构。

默认交付：图 + 可复用提示词。用户要图时不要只给提示词；环境不具备生成能力时，交提示词包并说明。

定稿前必须走「终检：去 AI 味」，见本文同名章节。

## 工作流

### Step 0 · 先定用途，再动笔

开工前确定五件事，缺哪件就在心里补默认值，不要为它们停下来问：

- **用在哪**：投屏 / 手机 / 文档内嵌 / 印刷 / 商品详情页。这决定信息密度与画幅。
- **给谁看**：专业读者还是普通读者，决定术语密度与解释深度。
- **是否承载信息**：图里要不要讲清结构、流程、数据。要，走信息型；不要，走表达型。
- **画幅**：横向 16:9 或 4:3，纵向 4:5、3:4、2:3，方形 1:1。
- **交付形态**：直接出图 / 只要提示词 / 图加图注。

第三问是分叉点，决定后面走哪条路径。

### Step 1 · 处理文案（仅信息型，或用户给了现成文案）

表达型且没有文案需求时，跳过本步。

排查五类问题：

| 问题 | 处理 |
|------|------|
| 歧义 | 指代不明的代词换成具体名词，多义词补限定 |
| 逻辑 | 因果、并列、递进关系说不通的重排或补连接 |
| 语法 | 成分残缺、搭配不当、语序问题 |
| 表达 | 口语碎句、重复、堆叠的修饰语 |
| 事实 | 数字、单位、专有名词前后不一致 |

**只产出与图相关的最小修订**：整理成一份可直接排版的内容清单，再列最多 5 条「改了什么、为什么」。不要交整篇润色报告，用户要的是图。

### Step 2 · 提炼画面意图

两条路径选一条。

**2A 信息型**：压缩成三层，作为版式与提示词的依据。

1. **一句话主张**：第一眼要记住的内容，通常就是主标题。
2. **信息块**：3~5 个并列或递进的块，每块一个短标签 + 一个图形或数据。
3. **层级**：主标题 > 信息块标题 > 说明文字，超过三层就砍。

块数超过 5 个时合并，或改成「总—分」两段式，不要靠缩小字号硬塞。

**2B 表达型**：定四个要素。

1. **主体**：画面里最重要的那一个东西，只一个。两个主体等于没有主体。
2. **场景与动作**：主体在哪、在做什么，给画面一个瞬间而不是摆放状态。
3. **情绪与基调**：冷静、温暖、紧张、未来感，用具体画面特征表达，不写形容词。
4. **关键细节**：材质、纹理、道具，两三个足够，多了画面会乱。

### Step 3 · 选图类型

**信息型**按内容关系选：

| 内容关系 | 图类型 |
|---|---|
| 并列的概念、能力、方案 | 卡片网格 / 对比双栏 |
| 前后步骤、流水线 | 横向流程 / 泳道 |
| 层级、包含关系 | 分层堆叠 / 同心圆 / 树 |
| 系统组成与调用 | 架构框图 |
| 时间推移 | 时间轴 |
| 数量与趋势 | 图表风格插画 |

**表达型**按画面用途选：

| 用途 | 图类型 |
|---|---|
| 卖产品、展示细节 | 产品图 / 静物摄影 |
| 传达人物与情绪 | 人像 / 场景人物 |
| 表达一个概念或氛围 | 概念插画 / 主视觉 |
| 封面、头图、banner | 海报式构图 |
| 图标、贴纸、表情 | 符号化图形 |
| 展示界面想法 | UI 概念图 |

具体骨架、必备元素与失败点读 [feature-image-types](references/feature-image-types.md)。选错类型比写得不好更致命：内容是对比却画成流程，再精致也没用。

### Step 4 · 写提示词

**四段必写**，顺序固定：

1. **画面主体**：画什么，一句话，先给类目再给特征。
2. **构图与视角**：主体位置、景别、视角、透视、留白。
3. **视觉风格**：摄影 / 扁平矢量 / 等距 3D / 线框 / 手绘，只选一种。
4. **画幅与画质**：比例、分辨率、清晰度要求。

**两段按需**：

5. **版式与分区**：信息型必写，表达型通常省略。几栏几块、位置比例、阅读顺序。
6. **图内文字**：图里需要字才写，逐条列出，标明层级与位置；不需要就明确写「画面无文字」。

再补**色彩与材质**（黑白或极简可省）：三到五色色板 + 主色用途；材质写明是哑光、金属、纸质还是玻璃。

最后是**负面约束**：不要水印、不要多余装饰元素、不要拥挤排版、不要风格混用。

写法细则、中英文提示词的取舍、参数怎么选，读 [core-prompt-anatomy](references/core-prompt-anatomy.md)。

### Step 5 · 生成与校验

生成后逐项检查，任一项不过就改**一个变量**再生成，不要一次改五处。

**通用项**

- 第一眼落在预期的主体或主标题上
- 风格单一，没有扁平与写实混用
- 配色在色板内，没有跑出第五种主色
- 元素无贴边、无重叠、无遮挡
- 画幅与目标载体匹配

**信息型追加**

- 信息块数量与顺序与 Step 2A 一致
- 图内文字拼写正确、无乱码、无多余字符
- 每个英文术语都有对应中文释义

**表达型追加**

- 主体只有一个，且不与其他元素抢视线
- 光影方向一致，没有多个光源打架
- 细节数量适中，画面不空也不乱

文字类问题往往改三次也修不好，这时改用「图内只留关键词 + 图外给图注表」，比硬修可靠。

## 硬约束

- **主体只留一个**：无论哪类图，第一眼只能落在一个地方。
- **风格只能有一种**：同一张图里不混扁平与写实、不混描边与无描边。
- **色板不超过五色**（写实摄影除外）：背景占大面积，主色一处，强调色只标关键点。
- **不写空话**：`高质量`、`8K`、`masterpiece` 这类词没有约束力，换成具体的构图、光线、材质描述。
- **不用装饰性英文**：模型爱在角落生成无意义小字，图不承载文字时直接在负面约束里禁掉。
- **中文排版**：提示词与图注遵循中文规范，全角标点、中英文之间留空格。

**图内需要文字时**追加三条：

- 单图标签总数不超过 12 个，中文标签不超过 8 字，英文不超过 3 个词。
- 英文术语必须带中文：优先「英文主标 + 小号中文副标」两行并排；标签太密时把释义移到图外图注表。
- 提示词末尾固定加一句「画面无其他文字」，并同步写进负面约束。

## 终检：去 AI 味（流程的最后一步）

这不是可跳过的附录。定稿前先跑扫描，再逐条过人工清单，两条都过才算交付。

`humanizer-zh` 在仓库里位于 `external/`，安装到编辑器后与其他技能平铺在同一 `skills/` 下，相对路径随布局变化。先定位脚本再跑，两种布局都覆盖：

```bash
SCAN=$(ls ../humanizer-zh/scripts/scan-ai-tone.mjs ../../external/humanizer-zh/scripts/scan-ai-tone.mjs 2>/dev/null | head -1)

node "$SCAN" 稿件.md   # 稿件已落盘
node "$SCAN" -         # 从标准输入读
```

扫描只负责把候选捞出来，判定标准在 `humanizer-zh/SKILL.md` 的 A–F 检查点（仓库内为 `external/humanizer-zh/SKILL.md`）。命中不等于必须改，承载实际信息的句子照原样保留。

必须清掉的六处：

- 空泛高频词：「赋能」「闭环」「显著提升」换成具体动作或数据
- 强凑三段式：有几项写几项，不为节奏删项或凑项
- 万能破折号：每处问一句「换成逗号或句号是否更清楚」
- 句尾拔高：结论停在事实上，不追加「这标志着……」
- 套话收尾：删掉「综上所述」「未来可期」「希望对你有帮助」
- 客服腔与免责填充：「值得注意的是」「需要指出的是」

底线是保留事实、否定、条件、归因、时间与完成状态，润色不许改变原意。
