# 文档工作流编排

用户丢来一个路径或链接，本技能负责两件事：按输入类型分流，在关键节点把结果交回用户看一眼。具体写作规则交给下游技能，不在此重复。

## 检查要快

这里的「快」指**少加载技能、少做检查**，不是弹窗响应快：

1. **分流只读元数据**：判断走哪条路线时，只看用户给的素材类型（目录 / 文件 / URL）和技能列表里的 description，不加载下游技能全文。
2. **一次只加载一个主技能**：选定路线后只加载这一条路线需要的主技能。教程路线 `tech-tutorial`；文档路线 `arrange-docs`（格式校对是它流程内的一步，不额外加载 `ruanyf-document-style-guide` 全文）；链接路线 clarify 之后只加载选定的那一个成文技能。
3. **不重复加载**：同一技能在一个流程里只加载一次。前面读过的 description、检查过的内容直接复用，不重新扫一遍。
4. **检查到够用为止**：教程检查跑一次脚本或一个清单核对就停；

## 用户输入工具

需要用户做选择时，**唯一方式是调用弹窗工具**——Claude Code 用 `AskUserQuestion`，其它运行时用它提供的等价选择弹窗。严禁在对话正文里输出编号选项、让用户打字回复。

1. **调用工具，不是发消息**：到了询问节点直接调弹窗工具，问题和选项全放进工具参数，附「不用了」出口。用户点选，不在聊天框打字。
2. **同步接续**：拿到选择就在同一个回合里继续下一步，不结束回合、不返回「等你回复」。
3. **弹窗只问一次**：一次只问一件事，最多 3 个选项，每个一句话说清后果，用户一次点选就定。
4. **没有弹窗工具时**：不询问、不列文本选项。直接按默认走完流程（正文交付即结束，不做插图、图床与知识库同步），并在交付里说明一句「当前环境无弹窗工具，已跳过后续确认」。绝不因为工具缺失就降级成文字提问。

判断依据是当前实际可用的工具列表。同一流程里用同一种弹窗方式，不中途换。下游技能内部如何提问按它们各自的规则；问完回到本技能，本技能的节点按本节执行。

## 分流（first hit wins）

Priority: 教程目录 > Markdown 文件 > URL 链接。按第一条匹配的走。

| 输入 | 路线 | 执行技能 |
|------|------|----------|
| 教程目录（多章 Markdown，含 `README.md` 或 `_meta.yaml`） | [教程路线](#教程路线) | `tech-tutorial` |
| 本地 Markdown 文件（单篇初稿） | [文档路线](#文档路线) | `arrange-docs` + `ruanyf-document-style-guide` |
| URL 链接 | [链接路线](#链接路线) | `clarify` → 按意图选 |

都不是时，按用户显性意图直接调用对应技能；不在没素材时空跑流程。

## 交点与后续

三条路线最终都落到这里。每步做完紧接着弹窗问下一步，拿到回答继续做，**全程一个回合走完**。按顺序最多三个弹窗：

| 做完这步 | 展示给用户 | 紧接着弹窗问 | 选项与后续 |
|---------|-----------|-------------|-----------|
| 正文产出 | 文件路径 + 一句话摘要 | 是否插图？ | 「插图」→ 加载 `baoyu-article-illustrator` 生成，完成后进下一行；「不用了」→ 跳到下一行 |
| 图片处理结束（或跳过插图） | 图片/文档路径，或图床链接 | 是否同步到远程知识库？ | 「同步」→ 按[远程知识库同步](#远程知识库同步)执行；「不同步」→ 本流程走完 |

图片上传与本地路径替换按 `picgo-upload` 技能的流程就地处理，不单独占一个弹窗；用户选了才做。

不要在用户看过正文之前调用插图技能。每行的执行方式统一是：做完 → 弹窗 → 拿到回答立即接着做。

## Step 1: 教程路线

加载 `tech-tutorial`，按其 Step 5 对齐检查执行：

- 三级目录 + 默认落位 → `python3 scripts/check_tutorial.py <教程目录>`
- 单文件或用户指定落位 → 人工清单核对
- 脚本只兜底机械项，提示不等于错误

完成后转入「交点与后续」。

## Step 2: 文档路线

只加载 `arrange-docs` 一个主技能。它自带删除无用信息、图文对应、重组章节、展开 `【（xxx）】`，以及排版与叙事的风格校对——格式规则由它在流程里调用 `ruanyf-document-style-guide`，本技能不重复加载、不自己逐段校对。

完成后转入「交点与后续」。

## Step 3: 链接路线

1. 加载 `clarify` 确认意图：解读 / 摘要 / 教程 / 其它，读者是谁，产出形态是什么。需要提问时按「用户输入工具」弹窗；用户说「直接做」「按你判断来」时 clarify 按其自身规则跳过。
2. 按意图选技能：

   | 意图 | 技能 |
   |------|------|
   | 论文、技术长文解读 | `ruanyf-paper-explainer`（自带全文抓取、结构骨架与公式规则） |
   | 教程类 | `tech-tutorial`（只给技术名时走其 Step 1 搜索） |
   | 其它写作 | 直接写，格式按 `ruanyf-document-style-guide` |

3. external 下的 `baoyu-article-illustrator`、`picgo-upload` 只在「交点与后续」按用户确认加载，成文阶段不抢跑。
4. 成文后转入「交点与后续」。

## 远程知识库同步

用户确认「同步」后执行。SSH 别名 `services`（`~/.ssh/config` 已配置，root@134.175.23.212），目标根目录固定为：

```
/data/knowledge-base/cockpit_desktop/knowledges
```

### 目录分类

按文档用途选一个子目录，没有就创建。已有同主题目录时沿用，不另起新类：

| 用途 | 子目录 |
|------|--------|
| 系统教程、学习路径、知识点梳理 | `tutorials/` |
| 论文解读、技术长文分析 | `papers/` |
| 整理后的初稿、规整成文 | `documents/` |
| 面试备考、求职材料 | `career/` |
| 其它或拿不准 | `misc/` |

子目录名用小写英文，文件名沿用本地文件名，不改中文名。教程是整目录产出时，连同子目录结构一起传，保持相对路径。

### 上传步骤

1. **先列清单**：本地找出本次流程实际修改或新增的文件（正文、图片、`_meta.yaml` 等），逐一确认存在。不上传无关文件，不上传整个工作区。
2. **连 SSH 建目录**（幂等，重复执行无副作用）：

   ```bash
   ssh services "mkdir -p /data/knowledge-base/cockpit_desktop/knowledges/<分类>"
   ```

3. **传文件**：优先 `scp`，保留原文件名。

   ```bash
   scp <本地文件> services:/data/knowledge-base/cockpit_desktop/knowledges/<分类>/
   ```

   目录用 `scp -r <本地目录>/ services:/.../<分类>/`。

4. **核对**：SSH 上去 `ls -l` 目标路径，确认文件数、文件名和大小；图片同步后确认 Markdown 里的引用路径仍是本地相对路径（图床链接不用改）。
5. **报告**：在对话里给出远端完整路径和文件清单。传输失败时保留本地文件，报告错误原因，不重试超过 2 次。

连接失败或权限不足时，不改写本地文件，也不跳过确认直接重试别的主机。

## 终检

写作类路线交付前按 `humanizer-final-check` 跑去 AI 味终检；教程路线按其 Step 5 自查清单执行，不另起一套。
