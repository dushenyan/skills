# 去 AI 味终检

任何中文文本技能交付前都走这一关：**先扫，再判，两层都过**。

## 为什么单独成技能

扫描脚本与六条清单此前被 13 个写作技能各自复制一份，分叉已经出现（有的版本多了「报告保留理由」要求，有的没有）。本技能是这条流程的唯一事实源；判定标准归 `humanizer-zh`，本技能不复制。

## 流程

### 1. 定位脚本

`humanizer-zh` 在仓库里位于 `external/`，安装到编辑器后与其他技能平铺在同一 `skills/` 下，相对路径随布局变化。两种布局都覆盖：

```bash
SCAN=$(ls ../humanizer-zh/scripts/scan-ai-tone.mjs ../../external/humanizer-zh/scripts/scan-ai-tone.mjs 2>/dev/null | head -1)

node "$SCAN" 稿件.md   # 稿件已落盘
node "$SCAN" -         # 从标准输入读
```

### 2. 逐条判定

扫描只负责把候选捞出来，判定标准在 `humanizer-zh/SKILL.md` 的 A–F 检查点（仓库内为 `external/humanizer-zh/SKILL.md`）。命中不等于必须改，承载实际信息的句子照原样保留。

必须清掉的六处：

- 空泛高频词：「赋能」「闭环」「显著提升」换成具体动作或数据
- 强凑三段式：有几项写几项，不为节奏删项或凑项
- 万能破折号：每处问一句「换成逗号或句号是否更清楚」
- 句尾拔高：结论停在事实上，不追加「这标志着……」
- 套话收尾：删掉「综上所述」「未来可期」「希望对你有帮助」
- 客服腔与免责填充：「值得注意的是」「需要指出的是」

### 3. 过底线

润色不许改变原意。事实、否定、条件、归因、时间与完成状态一律保留。

## 交付说明

- 默认只在对话里简要报告：扫了几处候选、清掉几处、保留了哪几处（一句理由）。
- 调用方技能若另有报告格式要求（如「每处保留都要在交付报告里逐条给出理由」），按调用方的要求办，本技能不覆盖。
