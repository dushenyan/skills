# 报告文档规整

输入是**已经存在的材料**：调研笔记、网页摘录、聊天记录、旧报告草稿。输出是一份能直接交付的正式报告。

## 切入点来自现有技能

本技能不重造写作规则，只补「多份材料合成报告」这一步：

- 删除无用信息与展开用户指令 → `arrange-docs` 的第一、二、四步
- 排版与叙事 → `ruanyf-document-style-guide`
- 交付前去 AI 味 → `humanizer-final-check`
- 链接、数字、日期等可机械核对的项 → 本技能的脚本清单

## 用户输入工具

需要用户做选择时，优先用当前运行时提供的弹窗工具（Claude Code 用 `AskUserQuestion`）。没有弹窗工具时按默认流程走完，不在正文里列编号选项让用户打字回复。

## 工作流

### 1. 材料盘点

列出所有输入文件，逐份读。建一张**事实清单**，列：事实/数字、出处、出现在哪份材料、是否与其他材料冲突。

筛选规则：
- 标注了来源的事实进入正文候选；没标来源的降级为「待核实」。
- 被 `【（xxx）】` 包裹的是用户本人的指令，不是要删的噪音，按 `arrange-docs` 的规则展开成正文。
- 营销话术、重复转载、与主题无关的段落删除，但事实、否定、条件、警告不能跟着一起删。

### 2. 读者视角分析

动笔前先在脑子里（或写入工作笔记）过一遍分析蓝图，不把它写进最终报告：

- **最值得保留的结论**：哪些是核心判断、反直觉事实、金句，读者读完最先记住什么。
- **结构诊断**：当前材料按什么顺序走？哪里该合并、哪里该拆开、哪里是大段文字需要变表格或列表。
- **读者真正需要的信息**：可执行结论、关键定义、埋在段落里的对比。
- **格式问题**：标题层级混乱、平行信息写成散文、术语与命令没标代码。
- **明显错字**：只改笔误，不改表述。

分析蓝图决定下一步的章节顺序与详略，不追加新内容。

### 3. 结构重组

按读者的顺序排章节，不按材料到达的顺序：

1. 结论摘要（3～5 句）
2. 背景与问题（为什么值得读）
3. 主体发现（按重要性，不按来源）
4. 对比与限制（按需）
5. 参考来源

同一事实在多处出现时合并到最相关的一节，其余位置用一句话交叉引用。

### 4. 来源与事实核对

机械项逐条过：

- 正文链接实际打开过吗？打不开的删除或替换。
- 数字、日期、产品名、人名与事实清单一致吗？有冲突就并列呈现，不择一。
- 表格里有没有裸 URL？改成 `[标题](URL)`。
- 有没有把「可能」「据说」写成确定事实？

这一步可以直接写一个小脚本做链接可达性和重复段落检查；脚本只兜底机械项，判断仍由 Agent 做。

### 5. 成文

加载 `ruanyf-document-style-guide` 按它的硬规则写：中英文空格、全角标点、短句、问题驱动开头。章节按 `##` / `###` 两级走，不跳级。用户指定格式、篇幅、读者时以用户为准。

### 6. 终检

按 `humanizer-final-check` 跑扫描脚本 + 六条清单 + A–F 判定，两层都过才交付。交付报告里说明：删了什么、合并了什么、哪些事实因为来源冲突保留双说法、终检命中项如何处理。

## 输出要求

- 默认写回用户指定的目标文件；未指定时新建 `<主题> 报告.md`。
- 交付报告分三块：材料处理（删/合/留的理由）、结构变化、终检结果。
- 不修改原始素材文件，除非用户点名要求。
